# 行情监控 App 需求文档（PRD）

- 版本：v0.3（决策定稿：双市场、自研图表、显示精度规则、CI 构建与发布）
- 日期：2026-09-19
- 状态：已评审，进入开发

---

## 1. 项目概述

### 1.1 目标
开发一款安卓行情监控 App，满足个人/小团队对加密货币行情的查看、分析与价格提醒需求。核心定位：**轻量、无后端、纯客户端**，所有行情数据来自币安（Binance）公开接口。

### 1.2 核心约束
| 约束 | 说明 |
|---|---|
| 平台 | Android（minSdk 26 / Android 8.0+，targetSdk 36） |
| 架构 | **无后端**：无私有服务器，客户端直连币安公开 API |
| 数据源 | 币安公开接口（现货 + 合约 USDT-M，行情类接口无需 API Key） |
| 更新分发 | GitHub Releases（CI 构建产物 APK），App 内检查并安装，见 4.6 |
| 图表 | K 线图 + 常用技术指标 |
| 提醒 | 本地价格预警 + Webhook 推送 |
| 账号体系 | 无登录，数据全部本地存储 |

### 1.3 目标用户
- 关注币安现货/合约行情、需要价格提醒的投资者
- 不信任第三方托管账号、希望数据不出本机的用户

## 2. 范围界定

### 2.1 本期范围（MVP）
1. 行情列表（自选 + 市场浏览），**覆盖现货与合约 USDT-M 两类市场**，市场类型在首页顶层切换
2. K 线图表 + 技术指标（含自定义周期）
3. 价格预警（本地通知）
4. Webhook 通知
5. 应用内更新（GitHub Releases 检查 + APK 下载安装）
6. 设置与数据本地持久化

### 2.2 明确不做（本期外）
- 用户账户、云同步、多设备漫游
- 交易/下单功能（只读行情；合约市场同样仅取公开行情）
- 衍生品高级数据：订单簿深度热力图、资金费率曲线、持仓量变化、多空比、清算数据（合约的 24h 行情与 K 线本期做，其余列入二期）
- 币安期权、交割合约、跨所行情
- iOS /桌面端
- 推送服务（不使用 FCM 自建推送，通知全部由本地产生 + Webhook 由用户自建接收端）

## 3. 数据源需求（币安公开接口）

### 3.1 接口选型（按市场类型分流）

**现货（REST 基址 `https://api.binance.com`）**
| 用途 | 接口 | 说明 |
|---|---|---|
| 服务状态 | `GET /api/v3/ping` | 连通性检测 |
| 交易规则 | `GET /api/v3/exchangeInfo` | 交易对、精度、状态，启动时同步一次并缓存 |
| 市场列表 | `GET /api/v3/ticker/24hr` | 24h 涨跌幅、成交量 |
| K 线 | `GET /api/v3/klines` | 官方固定周期 1m/3m/5m/15m/30m/1h/2h/4h/6h/8h/1d/3d/1w/1M；自定义周期由客户端聚合（见 FR-2.3） |
| 最新价 | `GET /api/v3/ticker/price` | 轮询兜底 |
| 行情推送 | `wss://stream.binance.com:9443` | `!<symbol>@miniTicker` / `@kline_<interval>` |

**合约 USDT-M（REST 基址 `https://fapi.binance.com`）**
| 用途 | 接口 | 说明 |
|---|---|---|
| 服务状态 | `GET /fapi/v1/ping` | 连通性检测 |
| 交易规则 | `GET /fapi/v1/exchangeInfo` | 合约交易对、精度、状态、onboard/update 时间 |
| 市场列表 | `GET /fapi/v1/ticker/24hr` | 24h 行情（字段与现货同构） |
| K 线 | `GET /fapi/v1/klines` | 周期与现货一致 |
| 最新价 | `GET /fapi/v1/ticker/price` | 轮询兜底 |
| 行情推送 | `wss://fstream.binance.com` | `!<symbol>@miniTicker` / `@kline_<interval>` |

> 两市场字段结构基本同构，数据层用 `MarketType`（SPOT / FUTURES）枚举集中管理基址、WS 地址、路径前缀与 DTO 解析差异；上层仓库、缓存、UI 只依赖统一模型（价格/成交量均以字符串传输，客户端按 BigDecimal 解析）。

### 3.2 数据层要求
- **REST + WebSocket 结合**：列表页用合并流（现货 `!miniTicker@arr`、合约 `!miniTicker@arr`）；K 线页用 `@kline` 流做最后一根蜡烛实时更新，历史用 REST 分页加载（每次 ≤ 1000 根）。
- **市场隔离**：所有行情实体、缓存与自选/预警记录均以 `(marketType, symbol)` 为主键，现货与合约同名交易对（如 BTCUSDT）互不覆盖；同一时刻只维持当前市场的一条 WS 连接。
- **限频保护**：遵守币安权重限制（现货 REST 约 6000 weight/min、合约约 2400 weight/min，客户端需做请求节流与合并）；WS 断线采用指数退避重连。
- **多域名容灾**：主域名不可达时切换备用域名（现货 mirrors / binancevision 等官方备用 endpoint，合约按官方公布的备用域），地址由设置项下发（见 8.设置）。
- **缓存策略**：最近一次行情快照、exchangeInfo、历史 K 线写入本地数据库，断网时展示缓存并标注"离线数据"。
- **不引入需鉴权的接口**（如账户、订单类），保证纯公开数据。

## 4. 功能需求

### 4.1 行情列表
**FR-1.1 自选列表**
- 添加/删除自选交易对；支持拖拽排序
- 每行展示：交易对、最新价、24h 涨跌幅（涨绿跌红或可配置）、24h 成交额
- **价格显示精度**（全 App 统一：列表、详情页、预警阈值与通知文案）：默认保留 **2 位小数**（四舍五入）；当交易对 `tickSize < 0.01` 时自动放开到 tickSize 的有效位数（如 `0.00004321`），避免极低价币显示 `0.00` 与虚假 0% 涨跌。仅为显示规则，内部计算与存储保持原始精度（BigDecimal / 字符串）
- 市场类型（现货 / 合约）在首页顶层切换，自选与预警按市场分别维护
- 实时刷新（WS），间隔异常时降级为轮询

**FR-1.2 市场浏览**
- 全量交易对列表，按 USDT / BTC / ETH / 其他计价币分类
- 搜索：按交易对代码、模糊匹配
- 排序：价格、24h 涨跌幅、成交额

**FR-1.3 行情详情页**
- 点击进入：当前价、24h 高低、24h 量额、K 线图表区
- 周期切换：1m / 5m / 15m / 30m / 1h / 4h / 1d / 1w，并支持用户自定义周期（见 FR-2.3）
- 支持横屏查看图表

### 4.2 K 线图与技术指标
**FR-2.1 图表交互**
- 蜡烛图，支持缩放（双指）、平移、十字光标、长按显示 tooltip（OHLC + 时间 + 涨幅）
- 主图叠加：MA（5/10/20/30/60 可调）、BOLL
- 副图指标（可多开窗格）：VOL、MACD、RSI、KDJ，二期扩展 ATR、CCI
- 指标参数可自定义并持久化

**FR-2.2 数据要求**
- 指标由**客户端本地计算**（基于 K 线原始数据），不依赖任何指标接口
- 首次进入加载最近 N 根（默认 500），下拉/左滑加载更多历史
- 图表配色与背景（明暗主题）可配置

**FR-2.3 自定义周期**
- 在官方固定周期之外，支持用户自定义 K 线周期（如 10m、45m、3h 等）
- 实现方式：**客户端聚合**——币安 API 仅提供固定周期，App 拉取基础周期数据后在本地合并生成蜡烛（O 取首根、C 取末根、H/L 取极值、V 求和）
- 聚合规则：目标周期须为所选基础周期的整数倍；基础周期取官方周期中**能整除目标周期的最大值**（如 10m 由 5m 聚合、3h 由 1h 聚合），控制拉取量 ≤ 币安单次 1000 根上限
- 自定义周期列表可增删并持久化，周期选择器中排在官方周期之后
- 实时更新：订阅基础周期的 `@kline` 流，将最新成交量/价格合并进当前未收盘的自定义蜡烛，无需额外请求
- 预警涨跌幅计算、指标计算均基于聚合后的蜡烛序列

### 4.3 价格预警
**FR-3.1 规则创建**
- 针对某交易对设置：上破价 / 下破价 / 区间外 / 涨跌幅达到 x%
- 触发模式：单次触发、每次穿越都触发、重复（每 x 分钟再次提醒）
- 目标价精度按交易对 tickSize 校验；输入框默认按 2 位小数提示，但对 tickSize 小于 0.01 的交易对允许更高精度输入（避免预警无法精确落位）

**FR-3.2 触发与检测**
- **无后台服务器**，价格检测由客户端完成：
  - App 前台：WS 实时检测
  - App 后台：前台服务（foreground service）+ 低频 REST 轮询（默认 30~60s，可配置）以平衡电量；Android 12+ 通知需用户授权
- 系统杀死进程后无法保证提醒 —— 在 UI 上明确告知该限制，并提供"保活提示"引导（二期评估 WorkManager 周期任务兜底，间隔 ≥15min，仅作尽力而为）

**FR-3.3 通知形式**
- 系统通知栏（声音/振动/锁屏，可按规则单独开关）
- App 内消息中心（保留最近触发记录）
- 触发时同步执行 Webhook 发送（见 4.4）

### 4.4 Webhook 通知
**FR-4.1 配置**
- 支持配置多个 Webhook 端点（名称 + URL + 启用开关 + 关联规则或全局）
- 内置模板变量占位符：交易对、方向、触发价、现价、24h 涨跌幅、时间
- 请求格式：POST JSON，payload 示例：

```json
{
  "event": "price_alert",
  "symbol": "BTCUSDT",
  "direction": "above",
  "threshold": 100000.0,
  "currentPrice": 100123.45,
  "changePercent24h": 2.31,
  "alertName": "BTC 破十万",
  "triggeredAt": "2026-09-19T08:00:00Z",
  "timestamp": 1789000000000
}
```

- 兼容常见生态：可自定义 JSON 模板，以适配 Discord/Slack/Telegram Bot/钉钉/飞书/Server酱 等（用户自备中转）
- 安全要求：URL 含 secret 参数，本地加密存储（见 6.安全）；仅允许 HTTPS（允许用户显式放开 http 用于局域网调试）

**FR-4.2 可靠性**
- 发送失败重试：指数退避，最多 3 次；最终失败写入消息中心并提示
- 提供"发送测试"按钮验证配置
- 防风暴：同一规则触发后冷却时间可配置（默认 5 分钟）

### 4.5 设置
- 主题：跟随系统 / 浅色 / 深色
- 语言：中 / 英（预留）
- 提醒默认参数：轮询间隔、冷却时间
- 行情域名配置（默认官方，可备用切换）
- 数据管理：清除缓存、导出/导入配置（JSON 文件，含自选与预警规则，便于换机）
- 关于：版本、检查更新（见 4.6）、免责声明（不构成投资建议）、第三方开源许可

### 4.6 应用内更新（GitHub Releases）
**FR-6.1 检查更新**
- 通过 GitHub REST API `GET /repos/{owner}/{repo}/releases/latest` 获取最新版本，按 release tag（约定语义化命名如 `v1.2.0`）解析出 versionName 与本地比较；若需按 versionCode 比较，则在 release 资产中附带 `manifest.json`（versionCode、apk url、sha256），二选一并在 M5 前定稿
- 触发时机：启动时自动检查（间隔可配置，默认 24h）+ 设置页"检查更新"手动触发；结果需明确反馈"已是最新 / 检查失败"
- 默认仓库地址内置于 App；设置页允许修改 `owner/repo`（便于 fork 或测试渠道）
- GitHub API 匿名限频 60 次/小时/IP，检查频率低，无需 token；失败（限频/网络/被墙）不提示打扰，仅手动检查时反馈

**FR-6.2 下载与安装**
- 发现新版本文案展示：版本号、更新说明（release body，Markdown 渲染或纯文本）、包大小
- 下载 release 中的 APK 资产（多 ABI 时需按设备架构选择或提供通用包），展示下载进度、支持取消；下载写入应用缓存目录，经 `FileProvider` 交给系统安装器
- 完整性校验：release 附带 SHA-256 校验值（或走 GitHub 资产自带 `digest` 字段，需在发布流程中填写），校验失败拒绝安装
- 权限：`REQUEST_INSTALL_PACKAGES`，首次触发安装时引导用户授权"安装未知应用"
- 更新流程为**提示式**：用户确认后才下载与拉起安装，不自动替换；下载/解析失败不得使 App 进入不可用状态
- 国内网络访问 GitHub 受限：提供可配置的下载加速前缀（镜像代理，默认官方直连），并允许跳过/稍后提醒

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动 ≤ 2s；列表滚动 60fps；K 线 1000 根渲染流畅（需高效绘制方案） |

| 离线 | 无网络时展示缓存数据 + 明确离线标识 |
| 更新 | 检查更新不阻塞启动（异步、静默失败）；APK 下载失败可重试，安装前完整性校验 |
| 可访问性 | 涨跌颜色同时用符号（+/−）区分，不全依赖颜色 |

## 6. 安全与隐私
- 全部数据存储于设备本地（Room/SQLite + EncryptedSharedPreferences 存 Webhook URL）
- 不采集任何用户行为埋点（或仅可选匿名崩溃上报）
- 无广告、无账号、无第三方 SDK 联网（除币安 API、GitHub 更新检查/下载 与用户自配 Webhook）
- 更新包仅从配置的 GitHub 仓库 Releases 下载并校验 SHA-256，不接受其他来源 APK；不内置静默/自动安装
- 权限最小化：INTERNET、POST_NOTIFICATIONS、（可选）FOREGROUND_SERVICE、WAKE_LOCK、REQUEST_INSTALL_PACKAGES（仅触发安装时引导授权）

开发环境约束：本机**无 JDK / Android SDK / Gradle**，因此编译与测试全部由 GitHub Actions 承担，PR 推送即以 Actions 日志作为反馈回路。

| 版本目录 | `gradle/libs.versions.toml` 单点管理 |
