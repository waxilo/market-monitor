## 现货测速改成「首答即回填」（双端，竞速替代等齐）

**定位**（不是网络问题）：两端 `probeSpot` 都是「一家 = 一串主机、并行打完整条链、等齐再取 min」。

## 缩放时 K 线贴在一起（用户带图，双端，2026-11-21）

**症状**：缩到比较密时整排 K 线糊成一条连续色带，分不清根数。
**根因**：实体宽 = `max(1, round(slot*0.66)) | 1`。槽宽 3.4px 时算出 3px（占 88 pct）、槽宽 2.4px 时
算出 3px（**比槽还宽**，直接吃掉邻居）；而且 `| 1` 是**向上**取奇，偶数一律 +1，等于系统性地多占 1px。

**改法**：抽出纯函数，双端同口径。
- 桌面 `chartMath.candleBodyRect(centerX, slot)`；Android `ChartViewport.kt` 的 `candleBodyWidth(slot)`。
- 上限 `floor(slot) - 2`（名义 2px 缝 —— 抗锯齿两侧各吃 0.5px，实测只剩 1px）；
  宽槽（实体 >= 7px）仍取奇数宽 + 整数左缘，柱心精确落回 `round(x)+0.5` 与影线严格重合；
  窄槽放弃奇数、让位给缝。`BODY_SHARE` 0.66 → **0.58**。主图蜡烛与成交量柱共用。
- 桌面 `BodyRect` 同时返回 `left`/`w`，KlineCanvas 里两处 `fillRect` 都用它。

**实测**（桌面 CDP，勾 `CanvasRenderingContext2D.fillRect` 读真实参数）：
槽 3.4px → 柱 1px/缝 2.4；槽 7px → 柱 4/缝 3；槽 24px → 柱 15/缝 9（常规档观感不变）。
Android 单测 5 条（`ChartViewportTest`，含 3~200px 全程扫「缝 >= 2px」）。

⚠️ **量这个别再走「一行像素 run-length」**：最新价虚线 dash `[4,3]` 周期正好 7px，它横贯全宽、
色段数常常比蜡烛行还多，量出来永远是「段宽 6、间距 7」（本轮在这上面白转了三轮）。勾 `fillRect` 才准。


## 切周期改成双段式加载（用户要求，2026-11-21 晚）

**要求**：切周期若还要取最新，不该先把已缓存的 K 线铺上去再静默替换 —— 应该先「加载中」，最新这段回来才上图。

**改法**（只动桌面端。Android 本来就是这套：`displayCandles` 在 `rawBase != baseOf(selected)` 时返回空，
`loadingCandles` 立刻为真，图上是 `ChartLoading` 的骨架 + 遮罩）：
- `ChartView` 取数 effect：`fresh = cached != null && isKlineFresh(key)`；**只有 fresh 才 `setCandles(cached)`**，
  否则 `setCandles([])` + `setLoad({ loading: true })`，画布自然走骨架分支。
- `KLINE_FRESH_MS` 60s → **5s**（≈ 两个实时节拍）。5s 内来回对比两个周期仍然零等待、零请求；
  更旧的缓存不再顶在前面。预热有自己的 `WARM_FRESH_MS = 60s`，两者解耦，别混。
- 缓存从此只当**退路**：请求失败 / 回来是空的 → `setCandles(cached)`；没有缓存才给「重新加载」空态。
  顺带修掉旧 catch 里的 `if (!alive || cached != null) return` —— 它会把遮罩**永久留住**（loading 从不撤）。

**实测**（`desktop/.workbuddy/tmp/verify-two-phase-load-cdp.mjs`，13 条全过）：
切 1m → 遮罩 595ms（一帧残影后全程骨架）、发 `1m/limit=200`；5s 内点回 15m → 无遮罩、无整段请求；
隔 6s 再切同一个周期 → 又先出遮罩（旧缓存不再顶在前面）。
截图 `two-phase-0-loading.png`（骨架 + 转圈，无蜡烛）、`two-phase-A-loaded.png`。
纯逻辑用例 `verify-kline-warm.mjs` 加了「上屏窗口 5s」与「预热 60s 另算」两条，13 条全过。

⚠️ CDP 观测桩的坑：`Page.addScriptToEvaluateOnNewDocument` 在 document_start 执行，
`document.documentElement` 可能还是 null ⇒ `observer.observe(...)` 抛 TypeError，**紧随其后装 fillRect 钩子的代码一起被跳过**；
现象是 `fills` 永远 0、`loadingSeen` 永远 0 —— 断言全在假通过/假失败。观察根退到 `document`，两个 try 分开写。


## 蜡烛的芯没在实体正中（用户带图，桌面端，2026-11-21 晚）

**症状**：缩到中密档（实体 3~7px）时，影线（芯）偏在实体一侧，且平移时一会儿偏左一会儿偏右。

**根因**：白天那版「留缝」改动里，窄槽（`wanted < 7`）为了保住 2px 缝，走了
`w = min(wanted, cap)` + `left = round(centerX - w/2)` 这条偶数宽/取整左缘的捷径。
影线是 `Math.round(x) + 0.5`（那一列像素正中），而实体中心落在 `round(centerX - w/2) + w/2`
—— 在 `centerX` 小数部分 ≥ 0.5 的那一半相位上正好差 1px。宽槽分支本来就是奇数宽 + 整数左缘，所以只有中密区歪。

**改法**：`candleBodyRect` 一律奇数宽 —— `w = wanted | 1`，超出 `floor(slot)-2` 就 `(wanted-1) | 1` 往下取一档；
`left = round(centerX) - (w-1)/2`（必为整数）。柱心恒等于 `round(centerX)+0.5`，与影线严格共线。
冲突时**让宽度不让对齐**（密区最多细 1px，看不出来；错位 1px 一眼可见）。量柱共用同一函数，一并修好。

**验证**：`verify-candle-gap.mjs` 117 条（含「任意相位 0/0.25/0.5/0.75/0.9 × 各档槽宽」柱心共线、左缘整数）；
`verify-candle-align-cdp.mjs` 钩 `fillRect` + `moveTo`，取**最后一帧**比对：默认档 106 实体、宽度中位 41px 档 18 实体、
中位 7px 档 92 实体，**每个实体中心都精确等于本帧某条 moveTo 的 x（容差 0.01px）**。截图 `align-A/B/C-*.png`。

**Android 不用改**：Compose 浮点绘制，`drawCandles` 的影线 `Offset(x, …)` 与实体 `x - half` 共用一个浮点中心，天然共线。

⚠️ CDP 踩坑：画布只在「数据变 / 手势 / 尺寸变」时重绘，`清空桩 → 等两个 rAF` 经常等不到任何一帧
（放大档抓到 0 个实体，看着像功能坏了）。改成桩里带 `performance.now()` 打点、扫描时取「最后一帧」
（时间戳差 < 6ms），随时读都准。

## 桌面划线：拖图表把线拖走了（2026-11-21 深夜）

用户：「上下移动图表，直线穿过的位置变了」（两张截图：同一段行情、同一时间窗，橙线与深色虚线的相对高低翻转）。

**实测复现**（CDP + 注入划线，1440×900）：
- 未选中时从线上起手上下拖 120px → 线不动、`pricePan` 仍 0（**图表也没动**，这一下只把线选中了）；
- 已选中后同样手势 → 线价 `57500 → 56288.84`，`pricePan` 还是 0（**图表没动、线跑了**）。
根因：水平线与趋势线在屏幕上都是**贯穿全宽**的，`LINE_HIT_PX`(4px) 命中带把画布横切成一条带子；
而当时口径是「已选中 + 按在线身 = 拖动这条线」。

**改法（编辑入口收敛到把手）**：
- 水平线：选中后两端各一枚圆点把手（`PRICE_HANDLE_INSET=8`/`HIT=7`）→ 改价；原先把两端 5px 短竖线当标记，正是
  「拖线身能改价」的误解来源；
- 趋势线：端点把手改角度（原有）+ **新增中点把手**（`trendMidHandles`）做整体平移；
- 线身命中（含未选中）只 `onSelect`，**落点继续走 pan**；`hitAnyLine` 保证「点线选中」不被「空白即取消」抹掉；
- 把手视觉：3.5+1px 描边在黄线上看不见（6 倍放大截图实证），改 **4.5 + 2px 纸色描边**。

验收：`verify-drag-safe.mjs` 8（拖线身只改 pricePan、线价不变；抓把手只改线价、pan 不变；含趋势线）
+ `verify-handles.mjs` 6（三枚把手坐标、中点两端同位移、端点只改一端）。回归 13+5+17+23 全绿。

⚠️ 踩坑：
1. **CDP 坐标要用页面坐标**（`canvas.getBoundingClientRect()` + 画布内 y），我第一次直接拿画布内 y 当页面 y，
   拖动全部落空、`pricePan` 恒 0，看着像「功能没生效」。
2. 截图尺寸（1080）与窗口宽（1440）不成 1:1，**别用截图目测像素**；`Page.captureScreenshot` 带 `clip+scale` 才看得清细节。
3. 手指/探针要抓 6px 的手把时**步长别粗**（我按 5% 宽扫描，正好跨过中点 30px 漏掉）；直接钩 `arc` 拿坐标最快。
4. `verify-float-badge-cdp.mjs` 的探测点 `cssW-8` 正好是右把手中心，改成 `cssW-30` 后 17/17。
