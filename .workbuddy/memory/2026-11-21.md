## 现货测速改成「首答即回填」（双端，竞速替代等齐）

**起因**：用户问「双端现货测速为什么每次都是 Gate 先测完、币安最后测完，可延迟不高」。

**定位**（不是网络问题）：两端 `probeSpot` 都是「一家 = 一串主机、并行打完整条链、等齐再取 min」。
币安 6 个 host 里 5 个在本机打不通，各跑满 5s 超时 ⇒ 回填时刻 = 最慢那条，显示值 = 最快那条。
本机实测：币安整行 **5142ms**（data-api 1621ms 通，api1~4 与主域各 5001~5013ms 超时），Gate **923ms**。
所以顺序恒定，且「延迟不高却最后测完」是同一件事的两半。

**改动**（结果导向，先立测试再改）：
- 桌面 `lib/sources.ts`：新增 `firstReachable(attempts)` 竞速（首个 ok 立刻 resolve；全挂 resolve 第 0 个=首选域的
  结论；空列表兜底一行文案），`probeSpotEndpoint` 改用它；抽出 `probeReason(error)` 与 `probeHost(host, call)`
  消除两处重复的失败折叠。
- 桌面 `lib/spotDialects.ts`：`SpotDialect` 增 `probe()` —— 币安 `/api/v3/ping`、Gate `/api/v4/spot/time`，
  替掉原来的 24h 行情探针（与 App 的 `pingPath()` 对齐，两端数字才可横比）。
- Android：新增 `data/remote/ProbeRace.kt` 的 `firstSuccess(attempts)`（supervisorScope + Channel；首个成功
  立刻返回并取消其余 job ⇒ OkHttp call 一起取消；全挂抛第 0 个异常；空清单 IAE）。`probeSpot` 改用它，
  去掉 `async/awaitAll/coroutineScope` 三个 import。

**验证**：
- Android 新增 `SpotProbeRaceTest` 7 例（虚拟时钟）：整行耗时=最快那条、返回值不被竞速改写、最快那条失败继续等、
  全挂报首选域（即使它最晚失败）、异常类型与文案不被包、其余探测被取消、空清单抛 IAE。`./gradlew
  :app:testDebugUnitTest` **全绿**（全量）。
- 桌面无测试框架，用 Node 内存转译真实 `sources.ts`（`typescript.transpileModule` + `new Function` + 只桩
  `httpRequest`）跑 7 个场景，10 条断言全过：1.5s 通+5 个 5s 黑洞 ⇒ 整行 1505ms（旧口径 5.1s）；Gate 311ms；
  全挂仍报首选域（含「首选最晚才挂」）。**没有落任何临时文件**。

**坑**：`TestScope.currentTime` 要显式 `import kotlinx.coroutines.test.currentTime`；协程栈回溯恢复会**复制**
异常，别断言 `error === original`，断类型+message。Gradle 全量编译 ~7min、增量重跑 ~1.5min（用
`init-builddir.gradle` 挪 buildDir，没打扰 IDEA）。

## 缩放时 K 线贴在一起（用户带图，双端，2026-11-21）

**症状**：缩到比较密时整排 K 线糊成一条连续色带，分不清根数。
**根因**：实体宽 = `max(1, round(slot*0.66)) | 1`。槽宽 3.4px 时算出 3px（占 88 pct）、槽宽 2.4px 时
算出 3px（**比槽还宽**，直接吃掉邻居）；而且 `| 1` 是**向上**取奇，偶数一律 +1，等于系统性地多占 1px。

**改法**：抽出纯函数，双端同口径。
- 桌面 `chartMath.candleBodyRect(centerX, slot)`；Android `ChartViewport.kt` 的 `candleBodyWidth(slot)`。
- 上限 `floor(slot) - 2`（名义 2px 缝 —— 抗锯齿两侧各吃 0.5px，实测只剩 1px）；
  宽槽（实体 >= 7px）仍取奇数宽 + 整数左缘，柱心精确落回 `round(x)+0.5` 与影线严格重合；
  窄槽放弃奇数、让位给缝。`BODY_SHARE` 0.66 → **0.58**。主图蜡烛与成交量柱共用。
- 桌面 `BodyRect` 同时返回 `left`/`w`，KlineCanvas 里两处 `fillRect` 都用它。

**实测**（桌面 CDP，勾 `CanvasRenderingContext2D.fillRect` 读真实参数）：
槽 3.4px → 柱 1px/缝 2.4；槽 7px → 柱 4/缝 3；槽 24px → 柱 15/缝 9（常规档观感不变）。
Android 单测 5 条（`ChartViewportTest`，含 3~200px 全程扫「缝 >= 2px」）。

⚠️ **量这个别再走「一行像素 run-length」**：最新价虚线 dash `[4,3]` 周期正好 7px，它横贯全宽、
色段数常常比蜡烛行还多，量出来永远是「段宽 6、间距 7」（本轮在这上面白转了三轮）。勾 `fillRect` 才准。
