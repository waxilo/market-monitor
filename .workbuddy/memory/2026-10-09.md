
## 2026-10-09 Android：进详情页「先冒一根柱子」+ 加载态改空图遮罩
- 用户反馈（截图）：进详情页图表先显示一根柱子，随后才跳出正确的 K 线图；要求加载中用「空图表 + 遮罩层」。
- 根因（两件事，第一件是主因）：`DetailViewModel.mergeBaseCandle` 里
  `if (list.isEmpty()) raw = listOf(update)` —— 实时增量流（`klineUpdate`，limit=2 的轻请求）
  必然快过首屏整页（`klines`，500 根），先到的那一根被当成整段序列画出来，整页到齐再整个换掉。
  截图里「较上根 --」+ 纵轴只有该根的高低值（81575~82400）正是单根序列的特征。
- 修法（重构式，不是打补丁）：给 `ChartData` 加 **`rawBase: CandleInterval?`**（已加载序列归属的
  **基础周期**），与 `raw` 成对更新；「哪一段序列就绪」由它说话：
  ① `displayCandles` 只在 `rawBase == baseOf(selected)` 时才派生展示序列（顺带修掉
  「换周期时把上一段蜡烛按新周期重新分桶」的假图）；② `mergeBaseCandle(base, tick)` 对不上就丢；
  ③ 增量流改带 base（`klineUpdate(...).map { baseOf(selected) to it }`）；
  ④ `loadingCandles = data.loading || (data.rawBase != base && data.error == null)`
  （只看 loading 不够：换周期那一帧可能排到「立 loading」之前，会闪一下「没有取到 K 线」）；
  ⑤ `baseInterval()` 收敛成 `baseOf(interval.value)`（不再可空），loadMore/OI 两处去掉 `?:`；
  ⑥ `loading = false` 从 `mergeBaseCandle`/`loadMore` 里拿掉 —— 加载与否由取数链独占。
- 加载态：新增 `ChartSkeleton(subCount, readoutLines)`（KlineChart.kt 内，与真实图共用 `ChartGeo`
  + `drawGridAndAxes`，只画网格/副图分隔线、不画刻度数字、**不挂手势** —— 骨架期 barCount=0 接手势
  会把可见根数夹成 1 写进持久化偏好）。DetailScreen 里 `ChartLoading(state)` = 骨架 + 55% paper 遮罩 + 转圈，
  竖屏与全屏两处空态分支都换成它（全屏换周期原本会误报「没有取到 K 线」）。
- 顺手消掉一处重复口径：读数带行数有两个取法（真实图按曲线标签数、骨架图按配置数），
  抽成 `ChartSeries.mainReadoutLineCount()` / `mainReadoutLineCount(maPeriods, showBoll)`，
  等价性由新单测锁死（不然数据到位的瞬间整张图会差一行往下跳）。
- 验证：`testDebugUnitTest` 全绿 **286**（283 + 新 3 条：两口径等价 / 裸 K 0 行 / MA+BOLL 2 行）。
  构建仍走 `-I ../.workbuddy/tmp/init-builddir.gradle --project-cache-dir ../.workbuddy/tmp/agcache`（1m26s、1m12s 两次都通）。
- ⚠️ **未做真机验收**：`adb devices` 为空（MuMu 没开，`adb connect 127.0.0.1:16384` 是启动 emulator 之后的事）。
  改的是 Compose 自绘逻辑，单测覆盖不到渲染，真机看一眼「进页面是骨架、随后一次成型」才算数。
