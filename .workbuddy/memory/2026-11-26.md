## 均线分析画线：默认无价签 / 不告警 / 对齐自动化（双端）

用户需求（原文）：「桌面端和app端的均线分析画线，默认无价格签、不告警。都支持手动设置为有价格签，
有告警。点击对齐保留用户设置。均线分析的画线更新了自动对齐，不要人点」。
澄清三点后定版：Android 存储**改成 `chart_line`**（不再一条规则一条线）、不告警的线**黄色 = 记号**
（红 = 会响）、已画过的行再点 = **直接删除**（不再保留「对齐到当前值」这一档，对齐交给自动）。

细节已归档：`android.md` / `desktop.md` 各自同日小节。要点：

- 桌面 `bindPriceLine` 去 alert 参数（病灶）、系统线默认 `showBadge = false`、`LevelLineDid` 去
  `'align'`、`ChartView.onLevels` 每轮 `alignLevelLines`；面板行标记分 `.on` 红 / `.mark` 黄。
- Android `MaOrigin` 身份 + Room v12（`chart_line` 加 5 列，`MIGRATION_11_12` 搬老数据）、
  `MaTick` 去 `Align`、`alignMaLines` 每轮对齐只改价位、竖栏编辑栏加价签/告警两枚按钮。
- 收编手画线时会话里抓到一个真实 bug：`showBadge` 隐式值随身份翻转 ⇒ 价签凭空消失，已在
  `bindPriceLine` 里钉住显式值。

校验：桌面 `tsc --noEmit` 通过 + 6 组 node 断言；Android `:app:compileDebugKotlin` OK、
`:app:testDebugUnitTest` 全绿（`MaAnalysisTest` 43 项）。两处收尾把面板里仍写「告警红底」
「图上落 / 对齐 / 删掉」的旧注释改成新口径，并把行标记颜色改成跟着线走（红=会响、黄=记号）。

⚠️ Android 侧未真机验收（沙箱起不了模拟器）：竖栏那两枚新按钮、黄线/红线观感、v11→v12
迁移后的老数据回显，需要用户在 MuMu 上看一眼再决定是否发版。

用户先口误说「直线」，当场纠正为「水平线」：「桌面端的水平线应该去掉抓点，任意位置都应该可以
拖拽。如果app端有这个问题，也一起修改」。这是**对 2026-11-21 那次决定的反转**（当时把改价入口
收成两端圆点，线身只选中，因为竖向平移图表会误抓）。

- 误抓代价用户知情并接受；日后要收敛就缩带宽，不要加回把手。

## 画线三档配色：普通＝中性、选中＝黄、告警＝红（双端）

用户：「水平线、直线改为黑色，选中状态统一为黄色，告警线统一为红色。双端都改」。
先问了两个必须定的点并拿到答复：①**黑色按主题自适应**（深色主题纸色 #0a0c11，纯黑上去等于消失
⇒ 深色用近白 #ecedef，浅色才是真黑 #14161a）；②**选中压过告警**（正在操作的那一条先看见黄）。

- 桌面：新 token `--line-plain`；`--line-mark` 收窄成「选中黄」；`Palette` 加 `plain`；
  水平线 / 直线 / 价签 / 备注牌四处统一三档取色；面板 `.ema-row.mark::before` 改 `--muted`。
- Android：`ChartPalette` 加 `plain = scheme.onBackground`（= Ink / InkLight，与桌面同值）；
  `drawDrawLines` 三档、`drawAlertLines` 选中转黄；`LineBadges` 加 `selected` 参数，价签底色跟线走；
  面板 `MaRow` 竖条改 `colors.muted`。
- 校验：桌面 `tsc --noEmit` + `npm run build`；CDP 像素级脚本 `verify-line-colors.mjs` **19/19**
  （浅色普通 rgb(20,21,25) / 选中 rgb(241,187,9) / 告警 rgb(224,47,68) / 再选中又回黄；
  深色普通 rgb(236,236,239) / 选中 rgb(246,187,14) / 直线 rgb(236,237,239)）；
  Android `:app:testDebugUnitTest` **493 项 0 失败**。
- ⚠️ Android 仍未真机验收：深色主题下近白线压 K 线够不够清楚、选中转黄的回执够不够快。
- 脚本踩坑记两条：`about:blank` 是 opaque origin，`localStorage` 直接 SecurityError（先导航再写）；
  `.interval-bar` 被指标栏与划线区共用，`at(-1)` 常拿到指标栏（改成全文档找 `.chip`）。

## 画线可切虚线（双端）

用户：「支持将实线设置为虚线，双端都支持」。

- 桌面：`PriceLine.dashed` / `TrendLine.dashed`（缺省实线、改回实线删字段）+ 两个纯函数 setter +
  编辑条一枚「虚线」chip；`DRAW_DASH = [8, 5]`，发光与线身同 pen。
- Android：Room **v13** 给 `chart_line` 与 `alert_rule` 各加 `dashed` 列（两条存储路径都要支持）；
  `DrawGuideLine.dashed` / `AlertPriceLine.dashed`；`lineDashEffect()`；竖栏编辑栏新增 `DashGlyph`。
  ⚠️ `toChartLine(existing=).base()` 必须带 `existing.dashed`，否则拖一下线就变回实线。
- 校验：桌面 `tsc --noEmit` + `npm run build`；CDP 像素脚本 `verify-line-dash.mjs` **14/14**
  （实线 coverage 1.000 → 虚线 0.782、79 个断口、刷新后保持、改回实线恢复）；
  Android `:app:testDebugUnitTest` **499 项 0 失败**（新增 `LineDashedMappingTest` 6 项）。
- 两个踩坑：① 画布透明，像素判据必须看 **alpha**（`rgba(0,0,0,0)` 会被当成纯黑，虚线空隙
  全被填平，第一版假通过）；② `6/4` 的 dash 在 1 倍屏上读不出断开（抗锯齿吃掉一半空隙），
  改 `8/5` 后真空 3px 才像虚线。
