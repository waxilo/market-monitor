## 修：macOS 首条系统通知弹「Where is use_default?」应用定位选框（用户报，桌面端）

- 根因：桌面通知走 notify-rust → mac-notification-sys 0.6.15；后者发**本进程第一条**通知前会先拿
  **字面量 `"use_default"`** 当应用名跑 `NSAppleScript`（`get id of application "use_default"`）去
  LaunchServices 找 bundle id（`ensure_application_set`，0.6.15 `src/lib.rs:136`）。系统里没这个 app
  ⇒ macOS 26 把「应用定位」选框弹到窗口上（截图文案与字符串逐字对上）、**通知卡在选框后面**
  （AppleScript 在投递之前跑）。正常路径一进程弹一次 —— 现有 0.1.16 的症状 = 每次启动后第一条告警弹框。
- 修法：`alert.rs` 把 `claim_app_user_model_id` 并入 `claim_notification_identity`（同名多平台分支：
  Windows 分支原样 AUMID，新增 macOS 分支）：`setup` 里先
  `notify_rust::set_application("com.waxilo.marketmonitor")`（notify-rust 在 macOS 根导出，与库内
  `ensure_application_set` 共用同一个 `Once`）⇒ AppleScript 永远轮不到；横幅归属/图标也才是
  MarketMonitor（不认领时库的兜底是 Finder/Terminal）。失败只 `warn` 不挡启动（dev 机没装过 app、
  LS 查不到该 id 时）。
- 证据：运行中即安装版 `/Applications/MarketMonitor.app`（0.1.16，14:13 启动）；`lsregister -dump`
  命中 `com.waxilo.marketmonitor`（含 `NOTIFICATION#:com.waxilo.marketmonitor`）⇒
  `LSCopyApplicationURLsForBundleIdentifier` 有值，启动时认领必成功。`cargo test --lib` 10/10 绿
  （本机 macOS 编译含新分支）。
- 待用户亲验：装新版后第一条告警通知应无选框、横幅归属为 MarketMonitor。
