### 顺带修掉的真实 bug：图表页 JS 资源泄漏 + 尺寸自愈失败
`app/src/main/assets/chart/index.html`：
1. **容器被硬设成 `window.innerHeight`**：加载期该值可能为 0 或与真实视口不符，撑出的假高度会让 `resize()` 一直"成功"，画布就永久停在错误尺寸（无法自愈）。改为**容器尺寸完全交给 CSS**（html/body/#chart 均 100%），不再写内联像素。
2. **每次 `render()` 都新建 `ResizeObserver` + `setInterval` 且从不释放**：切一次周期/指标就多留一套，多个计时器同时 resize 已销毁的实例。改为 `teardownObservers()` 在 `buildChart()` 开头先 `disconnect()` + `clearInterval()`，并让 `resizeChart()` 返回布尔值，拿到真实非零尺寸就立刻停表。
- 验证方式（可复用）：`.workbuddy/tmp/verify-chart-js.js` 用 CDP 驱动无头 Chrome —— Node 22 自带全局 `WebSocket`/`fetch`，`/json/new?<url>` 拿 page target，`Runtime.evaluate` 注入 200 根假 K 线后调 `MarketChart.render()`，断言：①无 `Runtime.exceptionThrown`；②延迟后 canvas 尺寸从初始 300x150 自愈到贴近容器（实测 461x518 / 容器 526x744）；③连续 render 6 次尺寸仍正确。
- ⚠️ 本机 `chrome.exe` 若在非标准路径，脚本用 `CHROME_PATH` 环境变量覆盖。

## 图表「边界与文字重叠」修复（同日 17:3x）

用户反馈：**「图标边界没做好，和文字重叠了」**（截图为详情页 K 线图）。

### 逐层定位（不能只看截图，要读 bounds 反推几何）
把 `uiautomator dump` 的 bounds 和 `ChartGeo` 的公式对起来算，发现是**三类**独立问题，不是一处：

1. **时间轴标签互相重叠 + 越出右边界**
   - 旧实现只按 `MAX_TIME_LABELS=4` 算 `step`，**完全不看标签实际宽度**。`MM-dd HH:mm` 有 11 个字符，1080px 屏上最多放 3 条，写死 4 条必然重叠。
   - 旧实现按**左边缘**定位（而非居中），标签整体右偏，视觉间隙更窄。
   - 最右一条会横跨到右侧价格轴上（截图里 `80150.00` 被压）。
   - 修法：`rememberTextMeasurer()` 量出 `sampleWidthPx` → `minGapPx = sampleWidthPx + 间隙`；`capacity = plotWidth / minGap` 反推能放几条；标签按**中心锚定**（`x - width/2`）。

2. **图例（开高低收/量）自由流，直接压在蜡烛和网格上**
   - `ChartLegend` 是 `Column` 里几行 `Text`，位置 `padding(8.dp)`，**行数随内容涨**，长价格串还会横穿到价格轴下面。
   - 修法：`ChartGeo` 新增 `legendHeightPx`（常量 `LEGEND_HEIGHT_DP = 62F`）+ `plotTopPx` / `candlesHeightPx`，**顶部预留固定图例带**；所有主图绘制从 `plotTopPx` 开始（不是 0）。OHLC 拆成「开/高」「低/收」两行，双倍余量。
   - ⚠️ 关键：`yOf(fraction, top, height)` 只认「相对顶边的比例」，**改 top 必须成对改 range 判断**（`y in plotTopPx..plotTopPx+mainHeightPx`），漏一处线条就画进图例里。

3. **纵轴刻度垂直定位硬编码 + 无间隙判定**
   - 旧版 `y - 6f` 硬编码，字高一变就偏；价格区间压窄时网格线挤成一堆、数字叠成乱码。
   - 修法：量 `labelHeightPx` → 居中用 `centerYPx - labelHeightPx/2`；相邻刻度间距 `< minGapPx` 就**丢掉下面那条**。
   - 抽出 `AxisLabel(text, x, centerYPx, labelHeightPx, ...)` 供主图/副图共用。

### 踩坑：修完第一版仍重叠（截图可见 `17:1817:23` 贴死）
加左边界 clamp（`coerceIn(0, plotWidth - width)`）后，**被夹进来的首条标签正好贴住第二条**，间距保证被 clamp 抵消了 —— 这是自己修出来的新 bug。
最终契约：**先夹位置，再判间距；间距不够就整条丢掉**（不是硬画）。
并把这段纯数学抽成 `ChartModel.timeLabelPlacements(centersPx, labelWidthPx, plotWidthPx, minGapPx, step)`，返回 `List<TimeLabelPlacement(index, leftPx)>`
—— 抽出来的理由：留在 Composable 里依赖 `TextMeasurer`，**只能靠截图肉眼看，回归了也不知道**。

### 新增常量（KlineChart.kt 文件末尾）
`MAX_TIME_LABELS=4`（上限，非实际条数）、`TIME_LABEL_MIN_GAP_DP=10f`、`AXIS_LABEL_MIN_GAP_DP=4f`、`SUB_PANE_TITLE_INSET_DP=6f`、`ChartGeo.LEGEND_HEIGHT_DP=62f`。
⚠️ `62f` 与图例行数**强耦合**：以后加一行图例必须同步改，否则图例又压到蜡烛上。

## 纵向拖动伸缩刻度 + 双指缩放 + 列表缩略图缺失（同日 17:4x）

用户反馈三连：
1. 图表右侧的金额，支持上下拖动进行伸缩；
2. 图表支持双指扩大缩小；
3. 列表为什么只显示一个缩略图（截图：BTC 有 Sparkline，ETH 空白）。

### 问题 3：Sparkline 只显示一个（根因是硬性要求 1h 周期）
- **用设备数据库直接取证**：`adb exec-out run-as com.waxilo.marketmonitor cat .../market-monitor.db` 导出后用 python sqlite3 查 `kline` 表。
  - 表名是 **`kline`**，主键 `(market, symbol, intervalKey, openTime)` —— 不是 `klines`，列名也不是 `symbolId`。
  - 查到 `BTCUSDT` 有 `o:1h`（500 行），`ETHUSDT` 只有 `o:15m`/`o:1m` —— 列表 Sparkline 硬要求 1h，ETH 取不到就被跳过 ⇒ 空白。
- **修法（`MarketRepositoryImpl.recentCloses`）**：先按请求周期读；读不到就查 `klineDao.cachedIntervalCounts(market, symbol)`（`GROUP BY intervalKey`），挑**已缓存里最粗的周期**回退读取。
  - 抽了 `readCloses(...)` 私有函数返回 `List<Double>?`（`null` = 该周期没数据），把「有没有数据」和「数据够不够（>=2 点才画得出线）」分开判断。
- **实测确认**：ETH 列表行已出现独立形状的 Sparkline ✅。

### 问题 1 & 2：纵向伸缩 + 双指缩放
- `ValueRange` 新增（JVM 可测，全在 `ChartViewport.kt`）：
  - `center`：缩放不动点取中位价 —— 否则一缩放整张图就跑掉。
  - `scaled(factor, base)`：以 center 为不动点缩放；量程钳到 `[MIN_SPAN_RATIO=0.08, MAX_SPAN_RATIO=12]`（相对原量程），防止缩成一条线或一个点。
  - `panned(deltaFraction, base)`：位移按**未缩放的原始量程**折算，不是当前量程 —— 否则放大 10 倍后拖同样距离会飞出去 10 倍。
  - `panLimit(base, currentSpan)`：**允许的平移比例闭区间**。⚠️ 这是几何收口的关键（见下）。
- 手势（`detectChartGestures`）：单指加**方向锁**，双指横轴管时间轴、纵轴管价格刻度。
- UI：`PriceScaleResetBadge`（`刻度已缩放 · 复位`），仅在 `priceZoom != 1f || pricePan != 0f` 时显示。

### 修掉的两个真 bug（都是实测截图才发现的）
1. **K 线溢出 pane**：`ValueRange.toFraction` 只钳到 `[-0.5, 1.5]`，越界蜡烛仍会画到 pane 外（窜进图例/时间轴）。修法：主图与**每块副图各自 `clipRect`**；十字光标**不裁**（它需要跨 pane 跟随）。
2. **纵向平移能把 K 线整屏拖出去**（❗本来是用户要的功能，做成了负体验）：
   - 起初用 `PAN_LIMIT = 1.2f` 纯比例钳位移 —— 8 次大幅拖动后画面只剩网格，用户没有任何线索回去。
   - 正解：**按几何重叠收口**。`panLimit` 让可视区与数据区的重叠 >= `min(可视跨度, 数据跨度) * MIN_VISIBLE_SHARE(=0.25)`。
   - ⚠️ **钳累积量本身，不要只钳渲染结果**：只钳渲染的话 `pricePan` 会一路涨到很离谱，反向拖要先走完空行程，手感像卡住。（一度就是这么写的，实测反向拖动完全没反应。）

### 第三个真 bug：图表纵向手势被父级 `verticalScroll` 吃掉
- 详情页整体是 `Column.verticalScroll`，图表在其中。纵向拖动**有时**调刻度、**有时**翻页 —— 取决于起手位置和滚动状态，看起来「时灵时不灵」。
- 修法：`awaitEachGesture` 里 **`awaitFirstDown` 后立刻 `first.consume()`**，并且每次 `awaitPointerEvent` 后 **无条件 `pressed.forEach { it.consume() }`**。父滚动容器于是拿不到事件，图表内的纵向手势语义唯一：调刻度。
- 实测双向往返（每次都从图表内部起手）：`2565.00` →（上拖5次）`2555.00` →（下拖5次）`2585.00`，两个方向都**即时响应、无空行程** ✅。

### 换标的要复位刻度
`KlineChart` 新增 `symbolKey: String` 参数（传 `state.id.storageKey`），`LaunchedEffect(symbolKey)` 复位 `priceZoom/pricePan`。

## 横向拖动：最新一根可以往左推、右侧露出留白（同日 18:0x）

用户两轮反馈：
1. 「现在 k 线画布支持上下拖动，也需要支持左右拖动」；
2. 「我看到左右拖动有效，但是最新的 k 线只能顶在最右边，不能往左拖」。

第 2 条是关键澄清 —— 横向拖动**本身能用**（说明累积取整那套没问题），真正的限制是 `ChartViewport.rightOffset` 的下界被夹在 0。

### 根因：`rightOffset` 的语义把「看更早」和「右侧留白」混成了一个量
旧实现里 `end = barCount - 1 - rightOffset`，且 `clamp()` 把 `rightOffset` `coerceIn(0, barCount-visible)`：
- `rightOffset > 0` ⇒ 窗口整体**左移**（看更早的历史），右侧留白恒为 0。
- 于是「把最新一根往屏幕里推」在数学上无解 —— 它永远贴在右边界。

**修正后的语义（务必记住）**：`rightOffset` = **右端越过最新一根空出的根数**
- `= 0` 贴最新价（默认）；
- `> 0` 最新一根被推向屏幕内偏左，右侧露出留白；
- `< 0` 窗口移向更早数据（`|offset|` 根历史移出右边界之外）。

⇒ `end = barCount - 1 + rightOffset`；`pan(deltaBars)` 变成 `rightOffset - round(deltaBars)`
（手指右移 = 看更早 = offset 变负）。`zoom()` 反推 offset 的式子同步改成
`O' = newStart + target - barCount`（原式符号写反了，anchor 测试全红才发现）。

### 必须拆开 `window()` 与 `plotRange()`
允许越界后，**索引安全**和**几何定位**不再是同一件事：
- `window()`：夹在 `0..barCount-1`，给**算量程**与**取数据**用（否则 `candles[i]` 越界崩）。
- `plotRange()`：含留白，可越出序列末根，给**横向像素定位/网格/时间轴**用。
- 所有 `drawXxx` 的 `xOf` 一律传 `plotRange`，取数据一律 `candles.getOrNull(i) ?: continue` / `bars.getOrNull(i)`。
- `indexAt()` 结果**夹回 `0..barCount-1`**（在留白区点按几何上落到末根之后，那里没数据，返回末根最贴近），否则十字光标拿到的下标会越界。
- ⚠️ 差点踩的坑：`window()` 改语义后**漏改 `plotRange()`**，两者只差一个符号，`grep` 时极易看漏 —— 用「有没有 `.last > barCount-1` 的单测」钉死。

### 留白上限复用 `MIN_VISIBLE_SHARE`
`maxRightBlank(visible) = visible * (1 - MIN_VISIBLE_SHARE)`，与纵向 `panLimit` 同一套「不许拖成空屏」原则。
顺带把常量从 `ValueRange.companion` 上移到 `ChartViewport.companion`（纵向那份改成别名引用），因为现在两个方向都要用。
⚠️ `MIN_VISIBLE_SHARE` 是 `Float`（`ChartViewport` 用），`ValueRange.panLimit` 做 Double 乘法时要 `* MIN_VISIBLE_SHARE.toDouble()`。

### 「拖不动」的另一半：每帧位移不足一根
`onPan` 拿到的 `deltaPx` 除以 `slot` 通常 << 1，`pan()` 内部 `roundToInt()` 逐帧抹零 ⇒ 表现为完全不动。
- 抽成纯函数 `ChartGesture.accumulateBarPan(remainder, pixelDelta, slotPx): BarPan(bars, remainder)`，用 **`toInt()` 向零取整**（保留符号），凑够一根才提交。
- 非法输入（slot 非正/非有限、delta 非有限）→ 本帧无位移但**保留既有零头**，别让一个 NaN 把累积量清掉。
- 每次手势按下（`onGestureStart`）把零头清零，否则上一场拖一半松手会跳一下。
- 换周期/换标的也要清（slot 变了，旧零头单位错配）。
- 新蜡烛到达时改用 `resize(size, keepRightOffset = true)`：用户可能正把最新一根推向左边，来了根新柱子不该把他弹回最右端。

### 结论 / 待办（需要用户决策，未擅自改）
要修必须**固定一把签名密钥**，任选其一：
1. **固定 debug keystore**：把一把 `debug.keystore` 提交进仓库（或作为 base64 Secret），在 `build.gradle.kts` 里显式指定 `signingConfigs.debug.storeFile`。改动最小，仍是 debug 签名。

`ChartViewport.zoom()` 内部 `(visibleBars * factor).roundToInt()`。可见 120 根时缓慢捏合一帧只让间距变 1px
（因子 ≈1.0033），`120*1.0033 = 120.4 → roundToInt() = 120` ⇒ **每帧都没变化**，30 帧纹丝不动 = 「无法放大放小」。

改为按「根数」累积：`PinchBar(bars, remainder)`，每帧最多提交 ±1 根，再用 `reportApplied()` 回冲
`roundToInt` 造成的「实际生效量 ≠ 请求量」差额。

**余量记账写错过两次（注释里留了）**：
1. 对数记账 `exp(total)` 一次性提交 → 一根根重算导致**冲过头**；
2. 对数余量 `total - stepLog*sign` → `stepLog` 随 bars 变，旧余量单位失效 ⇒ 漂移。
最终用**根数**记账。注意 `|remainder| < 1` **不是**合法不变量（一次快帧会折掉约 12 根，`|remainder|≈11` 是正常的未消耗手动量）。

**方向确认**：`pinchFactor(prev,cur) = prev/cur` ⇒ 张开手指因子 <1 ⇒ `bars*(f-1)` 为负 ⇒ 可见根数变少 = **放大**，
与 TradingView 一致（张开=放大=看得更少更细）。之前一度以为方向反了，是误判。

## 详情页首帧 K 线图错渲染 —— 重构式修复（同日 19:0x~19:4x）

用户反馈：「为什么会显示图一这种 k 线图，需要我切换一下才能恢复为图二」。
两张截图数据完全相同（同价、同 1h、末根都是 `09-20 19:00`），**差异只在视窗**：
图一时间轴 `09-20 05:00 → 17:00`、纵轴只有 `2540.00`、蜡烛挤在左下角大片空白；
图二 `09-16 09:00 → 09-20 03:00`、纵轴 `2350.00`、蜡烛铺满。⇒ 是 viewport 问题，不是数据问题。

### 根因：`ChartViewport.barCount` 是字段，靠 `LaunchedEffect` 事后对齐
`KlineChart.kt` 旧代码：
```kotlin
var viewport by remember { mutableStateOf(ChartViewport.initial(series.size)) }  // 首帧 series.size == 0
LaunchedEffect(series.size) { viewport = viewport.resize(series.size, keepRightOffset = true) }
LaunchedEffect(interval.storageKey) { viewport = ChartViewport.initial(series.size); /* 复位 */ }
```
三条叠加的失效路径：
1. **首帧 `series.size == 0`** —— `DetailScreen` 在 `candles.isEmpty()` 时不渲染 `KlineChart`，数据到货才首次组合，而 `remember { initial(series.size) }` 在初始化那一刻就定值了；
2. **`LaunchedEffect` 不参与当前帧绘制** —— 它在组合结束后的副作用里跑，「对齐」永远滞后 ≥1 帧；数据比视窗先到的那个窗口期就是错配的；
3. **`LaunchedEffect(interval.storageKey)` 首帧不执行**（key 首次组合即当前值）⇒ 只有**切周期**才让 key 变、effect 真跑、`initial(500)` 修正回来 —— 这正是「切换一下就好」的原因。

错配的连锁：`window()` → `clamp()` 用陈旧 `barCount` 算出**空区间 `1..0`** → `dataWindow` 空 → `autoRange` 退化成 `ValueRange(0.0,1.0).padded()` 兜底量程 → 蜡烛按错误量程压缩、BOLL 带飘出图外。**图一形态完全被这条链解释。**

⚠️ 排除掉的假设：一度怀疑 `remember(state.candles, ...)` 捕获了被重建的 List 实例 —— **不是**。`ChartSeries` 是 data class，`state.candles` 同一引用，不存在脱钩。

### 重构方案（用户偏好重构而非缝补）
1. **`ChartViewport` 删掉 `barCount` 字段**，改为所有方法的**显式入参**（`clamp(barCount)` / `window(barCount)` / `plotRange(barCount)` / `pan(d, barCount)` / `zoom(f, anchor, barCount)` / `startIndex(barCount)` / `endIndex(barCount)` / `fractionOf(i, barCount)` / `indexAt(f, barCount)`）。
   - 关键收益：`barCount` 与 `series.size` **在同一个表达式里取值**，结构上不可能再脱钩。
   - 旧的两个字段（`visibleBars` + `rightOffset`）**就是全部「用户意图」**，`barCount` 只是数据层的投影，本就不该存。
   - `initial()` 不再需要 `barCount` 参数；`resize()` **整个删掉**（视窗不带长度，「来了新蜡烛」= `barCount` 变大，`rightOffset = 0` 自然贴回最新）。
2. **复位改成「重建 `remember`」**：`viewport` / `crosshair` / `priceZoom` / `pricePan` / `barPanRemainder` / `pinchRemainder` 全部挂同一组 key `remember(symbolKey, interval.storageKey)`。
   - 复位天然发生在组合期、与 `series` 同帧生效；**三条 effect 全删**（`LaunchedEffect(series.size)` + 两个复位 effect），`LaunchedEffect` import 也删掉。
3. **首帧防御显式化**：`ChartGeo` 新增 `measured: Boolean`（由 `size.width > 0 && size.height > 0` 得到）+ `isUsable` 派生属性；`KlineChart` 里算一次 `val isReady = barCount > 0 && geo.isUsable`，绘制、三个轴标签、图例全部由它统一把关。
   - 旧写法拿 `geo.plotWidthPx <= 1f` 当哨兵，依赖 `ChartGeo.of` 里 `max(1f, ...)` 那个「为了让除法不炸」的权宜兜底值当判据 —— 现在两个魔数都消掉了。
   - `pointerInput` 的 key 由 `series.size` 改为 `barCount`（语义一致的局部变量）。

### 验证
- `:app:assembleDebug` BUILD SUCCESSFUL；`:app:testDebugUnitTest` **tests=180 skipped=0 failures=0 errors=0**。
- 单测同步：约 40 处 `ChartViewport(a,b,c)` 构造与无参调用改成传 `barCount`；新增 `BARS = 2_000` 常量给手势类用例；`applyPinch` 加 `barCount` 参数。
- **新增回归测试 `同一视窗对任意序列长度都给出正确窗口`**：同一个 `ChartViewport(100)` 对 `barCount = 120/100/520/6` 分别断言 `20..119` / `0..99` / `420..519` / `0..5` —— 直接钉死「视窗与序列长度不可能再错配」。
- 真机（MuMu `emulator-5554`）实测：冷启动 → 搜索 ETH → **首次进入详情页首帧即正确**（1h，窗口 `09-15 20:00 → 09-19 04:00`、纵轴 `2350.00`，与用户「图二」一致）；进入后 **2s 与 6s 两帧截图完全一致**，无「逐渐归位」过程；切 1h 亦正确。

### 复用教训
- **Compose 里凡「A 必须跟随 B 保持一致」，别用 `LaunchedEffect` 事后对齐** —— 副作用永远慢一帧，而首屏错渲染往往就发生在那几帧。要么把 A 变成 B 的派生量，要么用同一组 `remember` key 让它们在组合期一起重建。
- **`remember { mutableStateOf(f(x)) }` 在 x 首帧为「空」时是个陷阱**：初始化定值后不会自己跟着 x 变，必须显式给 key。
- 排除假设要讲证据：这次先否掉了「闭包捕获旧 List 实例」，才没往错方向改 `DetailScreen`。

## 修复应用内更新：固定发布签名（同日 19:4x~20:0x）

用户：「修复应用内更新」。这正是上一段记录的**阻塞级待决策项**（签名不固定 ⇒ 覆盖安装必失败），这次落地。

### 根因（复述）
`app/build.gradle.kts` 无 `signingConfig`，`release.yml` 跑裸 `assembleDebug` ⇒ 用 Gradle 自动生成的 debug keystore；
GitHub runner 一次性，**每次发版一把新钥匙** ⇒ 相邻 Release 签名不同 ⇒ `INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match`。
隐蔽点：「检查更新」走的是另一套机制（`releases/latest` + `VersionCompare`），一直正常，只有走到安装才暴露。

本轮复核：线上 `0.7.0` 仍是旧签名；仓库 Secrets **为空**（`gh secret list` 0 条）⇒ 确认确实未修。

### 落地方案（选「正式 release keystore」而非「固定 debug keystore」）
1. `keytool -genkeypair` 生成 PKCS12，alias `market-monitor`，RSA 2048，**有效期 30 年**。
   证书 SHA-256：**`cf2e20c74d1edd4d1fb290afee3b68ed1a18e20ac70a89e4ab5c43ec2d52f034`**
2. base64 写入 4 个 Secrets（`KEYSTORE_BASE64`/`KEY_ALIAS`/`KEYSTORE_PASSWORD`/`KEY_PASSWORD`），已确认写入成功。
3. `app/build.gradle.kts`：新增 `resolveReleaseKeystore()`，先读 CI 环境变量、再读仓库根 `keystore.properties`（已 gitignore）。
   **拿不到就返回 null ⇒ 降级 debug 签名**，保证本地开发/单测不被生产密钥卡住；门槛设在 CI 的指纹断言上。
4. `release.yml`：decode Secrests → `$RUNNER_TEMP/signing/release.keystore` → `$GITHUB_ENV` 的 `KEYSTORE_FILE` → `assembleRelease`
   → **指纹断言**（不符直接红，别等用户装不上）→ 其余产物命名/边车约定不变。
5. `keystore.properties` + `.workbuddy/signing/`（含 keystore、base64、README 备份说明，均不入库）。

### 踩的坑（有价值的）
- ❗**AGP 默认只做 v2/v3 签名，APK 里没有 `META-INF/*.RSA`** ⇒ 校验指纹**只能用 `apksigner`**；我最初写的 `keytool -printcert -jarfile` 报「不是已签名的 jar 文件」（这条已写进 release.yml 注释）。
- Gradle Kotlin DSL 里类型是 **`com.android.build.api.dsl.ApkSigningConfig`**，写 `SigningConfig` 会报 `Type mismatch: inferred type is SigningConfig but ApkSigningConfig? was expected`。
- 本机 `--offline` 跑 `assembleRelease` 会因 `lint-gradle` 未缓存失败 ⇒ 临时加 `-x lintVitalAnalyzeRelease -x lintVitalRelease`；**CI 有网，别加**。
- MuMu 的 adb 反复 `device offline`：`adb reconnect offline` + `wait-for-device` 可恢复；**把多步 adb 串在同一个 .bat 里一次跑完最稳**，分开多次调用容易撞上 offline。
- `adb shell echo xxx` 的输出**用 `> file` 重定向再读**才可靠（管道里读回显偶发为空）。
