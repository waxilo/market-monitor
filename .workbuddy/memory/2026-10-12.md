
## 2026-10-12 桌面端：换标的/周期/数据源改成「骨架 + 遮罩」（对齐 App 的加载态）

- 需求（用户原话）：「桌面端切换周期加载时都需要遮罩层、空画布、加载中让用户感知」。
  即 10-09 在 Android 侧做过的那件事搬到桌面端（那边的记录见 2026-10-09.md 第一条）。
- ❗**先说清楚旧行为不是「空白」而是「上一张图留着不动」**：`KlineCanvas.draw()` 里
  `if (n === 0) return` 是**提前返回、clearRect 在它后面**，所以换周期后屏幕上仍是上一张图，
  而新周期的 chip 已经高亮 —— 观感就是「点了没反应」。这是这次要修的真问题，不是「加个转圈」。
- 改动（3 处，都在前端）：
  - `KlineCanvas.tsx`：新增 `SKELETON_RANGE = {low:0,high:1}` 与 `drawSkeleton(ctx,p,plotW,gh,paneCount)`
    —— 只画主图网格 + 每块副图的上边界分隔线；**不画**刻度数字 / 蜡烛 / 均线 / 读数带 / 最新价 /
    时间刻度（读数为空时全是 `--`，比留白更吵）。`draw()` 里把 `n === 0` 的早返移到 dpr 尺寸与
    clearRect **之后**，改成「画骨架 + return」。
  - `KlineCanvas.tsx` 渲染层多包一层 `.chart-stage`（`position:relative`）—— 遮罩必须盖**可视区**，
    而 `.chart-scroll` 是滚动容器（副图多时内容更高），遮罩塞进滚动内容里会跟着滚。
    `.chart-loading`（绝对定位 + `--scrim-chart` 半透明 + 转圈 + 「加载中…」）挂在它上面。
  - `ChartView.tsx`：`load = {loading, failed}` + `reloadSeq`；`setCandles([])` 的同时立 `loading`，
    `.then` 落、`.catch` 落并置 `failed`；`loading` **初值给 `true`**（首帧还没跑取数 effect，
    否则先闪一下「没有取到 K 线」）。取完仍无数据时改渲染 `.chart-empty`（提示语按 failed 分两句）
    + 「重新加载」按钮（`reloadSeq++`），此时画布整个卸载 —— 不做这一步，失败就是永久空白、没有出路。
- ⚠️ 两个实测出来的坑（都是先做完再被截图/断言纠正的）：
  ① **骨架网格不能用 `--hairline`**：它上面还盖着遮罩，浅色主题下实测对比度只剩 3.5%，截图里基本看不见，
     观感退回「一块空白 + 转圈」。改用 `--hairline-strong`（代码里读 `p.edge`）+ 遮罩降到 **0.5**，
     透过遮罩看浓淡与真实图的网格相当。新增 token `--scrim-chart`（两套主题各一份）。
  ② **逐帧验证里「观测窗」不能与「数据到达时间」重叠**：第一版把网络延迟设 1.5s、逐帧录音也跑 1.5s，
     窗口尾巴录到的其实是「新数据刚回来」那一帧（同样是「新周期高亮 + 有蜡烛」），被误判成旧图残留。
     把延迟拉到 4s、观测窗收到 1.2s 才成立。
- 遮罩顺带挡住画布手势（`position:absolute; inset:0`）—— 这是必需的：数据没到时拖拽/缩放会把
  没有意义的视窗写进 `mm.chartView`，下一张图就被带歪（App 的骨架图也刻意不挂手势，同一个坑）。
- 验证：新写 `.workbuddy/tmp/verify-chart-loading.mjs`（无头 Chrome + CDP 驱动**真实 Vite 页面**，
  浏览器下 `lib/http.ts` 退回 `fetch`、默认源 Gate 带头 CORS ⇒ 吃的是真行情），**20 条全过**。
  关键几条：加载中画布**正好 5 条**横贯绘图区的线（`ink == rows × plotW`=942px；6 个量程点里最下面
  那条被主图 clip 裁掉，真实图用的是同一个 clip）；骨架与真图 `cssSize`/`bitmap` 完全相同（版面不跳）；
  真实图 435 行墨迹 vs 骨架 5 行；逐帧对照 69 帧里没有一帧还留着旧蜡烛；深色主题另跑一遍同款断言；
  拦掉 `*gateio*` 时给的是「重新加载」而不是无限转圈，放开后点它能恢复出图。
- 配套：`tsc --noEmit` + `vite build` 干净；README 的「桌面端交互约定」补了这一条。
  **没有跑 `cargo build`** —— 纯前端改动，且用户本机 dev 应用在跑（那会让构建 LNK1104，见 MEMORY 的告诫）。
- 未发版：改动落在工作区未提交。

## 2026-10-12 Android：全屏划线竖栏收窄 + 「垃圾桶 → 点线删除」

- 需求（用户原话）：「1. app 端右侧的划线太大了，和页面不协调，进行修复；2. 划的线无法删除」，
  随后追加「在划线栏添加一个垃圾桶，点击垃圾桶，再去点线进行删除」，并要求「改完发到 MuMu 模拟器」。

  用户截图（1536×864）是设备图（1920×1080）的 0.8 倍，像素里量出竖栏灰底左沿 1781 → 实测 1820
  （139px=46dp → 100px=33dp），与常量改动吻合。
- **第 2 条其实是三个独立原因叠在一起**，只修一个都不成立：
  ① 底部提示单行 88 字在 640dp 横屏被父容器裁掉，**「拖到右上角垃圾桶删除」正好落在被裁的那半**
     （改短文案 + `maxLines=2` 兜底）；
  ② 垃圾桶只在**拖动进行中**才浮现 ⇒ 用户根本不知道有这回事（改成「工具激活 + 有同类线可删」时常驻）；
  ③ ❗**抓取判定错了**：`awaitFirstDown()` 已经把 down 消费掉，循环里第一帧 `awaitPointerEvent()`
     拿到的其实是**第一个 MOVE** —— 手指一动就滑出 `grabPx`(24dp)，「按住线拖走」被判成「新建一根」，
     松手在垃圾桶上只是丢掉新草稿，原来那根纹丝不动。修法：把抓取搬到 down 那一刻
     （`first.position`），与直线工具本来就是同一种做法。
- **第 3 条（用户后补的要求）：竖栏加第 4 枚「垃圾桶」+ `DrawTool.ERASE`**，点它再点图上任意一条线即删。
  比拖到角落直观得多，且与另外三枚共享同一套单选/自动收起规则。实现要点见 `android.md`。
- 实测（MuMu，adb `input tap` / `input swipe`，全部核对 Room 库）：
  水平线 `chart_line` 6→空；直线 id=7 点中点→空；告警线 `alert_rule` 52→0（`alert_state` 无残留）。
  **误滑不删的保护也验了**：在垃圾桶模式下横滑穿过直线，`chart_line` 仍为 7。
- 编译：`assembleDebug` + `testDebugUnitTest` 均过。本地构建仍走 `-I ../.workbuddy/tmp/init-builddir.gradle`
  （用户开着 IDEA，`android/app/build` 被占；用独立 buildDir 是唯一能跑通的方式）。

## 15:45 全屏划线：单击即落线（同一天的后续反馈）

- 用户反馈：「水平线和告警线选中后，单击无法划线，需要拖动一下才划线」。
- 根因在上一轮那次修复的余波：抓取搬到了 down，但**首帧落点仍然只发在循环体里**，
  轻点时循环首帧 `pressed` 已空、`break` 又排在循环体之前 ⇒ 循环体一次都不进。
  （上一轮没暴露，是因为那时"手只要动 1px"就会发帧，而用户从没试过"点一下不动"。）
- 修法：down 定性之后**立刻补发一帧** `onHorizontalDrag(grabbedId, y)` 并置 `dragActive = true`，
  与循环里那帧同源；`dragActive` 语义随之从「拖过」改成「这场落到线上」。
- **做了前后对照**（模拟器上当时装的正是含上一轮改动、未含本次的旧包，不必重编译就拿到"修复前"）：
  ① 旧包：点水平线工具 → `input tap 900 600` → `chart_line` 仍 **0**；截图显示工具已选中、
     垃圾桶已出现、底部提示正常，就是图上没线 —— 对照组成立；
  ② 装新包后同一动作：落 1 行 `id=11 kind=h price=83754.20`（y=600 按刻度线性换算 ≈83753.5，吻合）；
  ③ 告警线同样：`input tap 900 400` → `alert_rule` +1（`id=54 BTCUSDT reach 85015.1`）。
- 回归：拖线到右上角垃圾桶仍能删（桶变红、松手后 `chart_line` 空）；`DrawTool.ERASE` 点选删除仍正常
  （顺手用它清掉测试留下的那条 BTC 告警线，`alert_rule` 回到用户原有的 2 条 ETH）。
- 测试数据已清理；模拟器上跑的是新包。`assembleDebug` + `testDebugUnitTest` 通过。
- 文档：`README.md` 新增「Android 端画线交互（改之前先看这几条）」（与桌面端交互约定同体例）；
  `android.md` 的画线章节补「单击也要落线」。
