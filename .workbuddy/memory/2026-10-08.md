## 2026-10-08 桌面端：悬浮窗切换后的黑色描边（DWM 焦点边框）
- 症状：主窗切悬浮窗瞬间，胶囊外多一圈 1px 黑边，点别处失焦才消失（用户截图）。
- 根因：Win11 给**持有焦点的前台顶层窗口**描一圈 DWM 边框；`to_mini` 里 `show() + set_focus()`
  让悬浮窗成为前台。`ShowWindow(SW_SHOW)` 本身就激活 ⇒ 「不抢焦点」修不掉。
- 修法：新建 `src-tauri/src/frame.rs`，`create_mini` 里调 `frame::clear_focus_border(&window)`——
  `DwmSetWindowAttribute(DWMWA_BORDER_COLOR, DWMWA_COLOR_NONE=0xFFFFFFFE)` 永久关掉这圈系统边框
  （悬浮窗自己的描边由 CSS 画）；Win11 专属 API，Win10 调用失败静默忽略（那边本没这圈边）；
  属性跟窗口生命周期一致，创建时设一次即可。焦点行为（快捷键兜底、awake 判据）不受影响。
- Cargo.toml windows features 补 `Win32_Graphics_Dwm`。cargo check + 11 条单测全绿。
- 真机验收留给用户（dev 跑起来切一次悬浮窗看边框是否消失）。

## 2026-10-08 预警条件聚合：上破/下破 → 达到（app 端）
- 需求：手动预警编辑页不再让用户选上破/下破，只留「达到」；方向由系统在触发时按实际穿越自动判定，
  通知文案仍按方向显示「上破/下破」。
- 实现：`AlertCondition` 新增 `REACH("reach","达到")`（双向到达：相对上一次观测穿越目标价即触发，
  压在目标价上也算碰到）；ABOVE/BELOW 退为划线引擎内部条件，编辑器选项收进 `EDITOR_CHOICES`。
- 判定：`AlertEvaluator.satisfiedOf/directionOf` 增加_previous（=state.lastPrice）参数；
  REACH 首次观测无前值时返回 false 走基线建档（不能返回 null，否则永远建不了档）。
  引擎 `changed()` 只在语义字段变化时落库 ⇒ state.lastPrice 可能滞后，但穿越检测用
  「存的上一价与当前价分居目标价两侧」恰好不受滞后影响。
- 迁移：`AlertEntities.toDomain()` 读时迁移——source=MANUAL 且 condition∈{above,below} ⇒ REACH；
  指标划线规则（INDICATOR）保持 above/below（均线带靠方向条件区分上下锚，不能合并）。
- 图上拖线（DetailViewModel）：commitAlertLine 不再需要 referencePrice 判方向（连带删掉该函数），
  新建/拖动手动线统一落 REACH，名字「{symbol} 达到 {price}」；指标规则拖动只挪价位不动条件与名字。
- 测试：AlertEvaluatorTest 加「达到双向穿越+方向判定」「同侧移动不触发」，validator/文案测试补 REACH；
  `testDebugUnitTest --tests domain.alert.*` 全绿（1m13s，init-builddir 迁移构建目录方案照旧好用）。
