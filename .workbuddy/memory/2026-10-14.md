## 踩坑（值得记）

- **`Page.navigate` 回到同一个 URL 不会重载**（`#/mini` 与当前同址 ⇒ 同文档导航）。
  换场景必须 `Page.reload`；第一版深色那轮的断言失败就是这么来的（读到上一轮的 `data-theme`）。
- **vite 只绑 `localhost`**，而本机 `localhost` 解析到 IPv6 `::1` ⇒ 探 `127.0.0.1:<port>` 会
  connection refused，现象很像「dev server 没起来」。脚本里一律用 `localhost`。
  另外 vite **冷启动首帧要 30s 上下**（依赖预打包），首次导航的等待预算要给足。
- 断联判定**不要一拍就翻**：一拍全败多半是抖动，遮罩会闪一下又撤，比不做还吵。

### ② 全屏解锁态直接拖线 + 拖到竖栏变垃圾桶

「修改范围 = 解锁后直接拖动，不必选工具」。新增 `KlineChart` 参数 `linesEditable` /
`lineDropToTrailingRail` / `onLineDropDelete`；线条身份抽成 `sealed interface LineRef`
（`Alert(ruleId)` / `Guide(lineId)`），水平类抓取统一为 `HorizontalAnchor(ref, yPx)` +
`closestHorizontal` / `nearestHorizontal`。

- 解锁态抓取在 **down 那一刻**定性，水平类与直线**放在一起比距离**取更近的（分两次判再定优先级会
  「按着看得见的那条、拖走底下那条」）。
- 垃圾桶落点用**原始** x（`lastRawX`，不夹进绘图区）：逐帧那份 x 已夹在 `0..plotWidthPx` 内，
  永远到不了竖栏所在的画布右缘之外。落点是**拖线时才出现的整栏高亮**（对比 2026-10-12 撤掉的
  「画布右上角常驻垃圾桶」——那次失败正是因为落点平时不存在）。
- 「正在拖」的唯一事实来源是线自己的 `dragging` 标记（`alertLines` / `drawLines` 里都有），
  不另报布尔 —— 布尔漏收尾会让竖栏永久变成垃圾桶。

## 晚间追查：桌面端 0.1.24 应用内更新失败（僵尸进程占住 exe）

用户截图 "Failed to kill MarketMonitor. Please close it first then try again"。层层探到根因：

- Tauri NSIS 安装器杀运行中应用**不走 taskkill**，走 **Restart Manager**：
  RmStartSession → RmRegisterResources(安装目录 exe) → RmGetList → RmShutdown(RmForceShutdown)，
  失败返回 351（ERROR_FAIL_SHUTDOWN）→ 弹 "Failed to kill"（模板在 utils.nsh 的
  `CheckIfAppIsRunning` 宏，tauri-cli 2.12.0 可从 GitHub raw 读到）。
- %TEMP% 里 18:22 与 18:29 各有一个 `MarketMonitor-0.1.24-updater-*`（两次应用内安装尝试）；
  之前 0.1.19→21→22→23 全成功，今天第一次挂。
- 现场证据：`market-monitor.exe` pid 17872（昨天 09:07 启动的 0.1.23）**窗口全灭**
  （EnumWindows 空）、WebView2 子进程全灭，但进程活着、占着 exe —— **退出清理挂死的僵尸**。
- 探针复现（.workbuddy/tmp/rm_probe.py / rm_shutdown_test.py / term_test.py / ppl_query.py）：
  RM 只列出 17872 一个占用者；`RmShutdown(RmForceShutdown)` 返回 **351**；
  `OpenProcess(PROCESS_TERMINATE)` 成功但 `TerminateProcess` 返回 ACCESS_DENIED(5)
  （注意：本机探针在沙箱里跑，这步 gle=5 可能掺了沙箱因素，但安装器 351 是真实世界的）；
  非 PPL（NtQueryInformationProcess(61) flags=0）、无 AV 进程。
- 根因链：插件 `Update::install`（Windows）= ShellExecuteW 起安装器 → `std::process::exit(0)`
  硬退出 → **挂死在退出清理**（tao 0.37.1 的 WM_ENDSESSION 处理也是 `loop_destroyed()`+
  `process::exit`，tauri#14479 社区正讨论这条路径的坑）→ 僵尸占 exe → 安装器 RM 关不掉 → 中止。
- **修复（已落 update.rs，cargo check 过）**：Windows 不再用插件 install —— 自己落盘
  （%TEMP%\MarketMonitor-{ver}-updater\）、`Command::spawn` 带 `/P /UPDATE /R`
  （passive+更新模式+装完自动重启；/R 只在 passive/silent 生效，来自 installer.nsi 的
  `.onInstSuccess`），然后 `app.exit(0)` 优雅退出（与托盘 quit 同一条路）。macOS 不变。
- 待办：用户从任务管理器杀掉 17872 僵尸（不行就重启）→ 手动跑
  %TEMP%\MarketMonitor-0.1.24-updater-LkEVj5\MarketMonitor-0.1.24-installer.exe → 0.1.24；
  修复随下一版（0.1.25）发布，下一轮应用内更新才能吃到。
- 诊断工具沉淀：沙箱里 tasklist 看不到进程 ⇒ Toolhelp 快照 python 脚本（proc_scan.py）；
  ctypes 查 RM：函数名是 **RmRegisterResources**（不是 RmRegisterFiles，想当然会
  AttributeError）；wt.SYSTEMTIME 不存在要自己定义；argtypes 不显式设会段错误。
