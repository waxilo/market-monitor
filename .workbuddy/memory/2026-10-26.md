# 2026-10-26

## K 线：横向平移松手不再重排纵轴（Android，用户报「K 线跳动」）

用户原话：「移动端向左拖动查看历史 k 线时，会自动把 k 线设置到画布中间，用户会觉得 k 线跳动，去掉这个逻辑」。

### 复现（MuMu，0.9.54 debug）

`input motionevent DOWN/MOVE…/UP` 分帧截图：拖动中价格轴冻结（刻度停在旧窗口的量程），
松手那一帧整张图重排 —— K 线纵向下移约 50px、刻度从 79500–81000 跳到 78000–82000。
真因是 `KlineChart` 的 `priceBase`：`onGestureStart` 冻结、`onGestureEnd` 清空，
松手后 `rangeBase` 立刻换回新窗口的自动量程，量程与中心一起变。桌面端当时根本没有冻结
（价格轴逐帧跟随）—— 表现是拖动全程持续缩放，同一问题另修（见文末「桌面端」一节）。

### 改法

- `ChartViewport.kt`：新增 `PriceIntent(zoom, pan)`、`ValueRange.intentFor(target)`（绝对量程 → 相对本量程的意图，
  与 `scaled()` + `panned()` 的回放式一一对应）、`ValueRange.overlapShare(other)`。
- `KlineChart.kt`：`onPan` 记 `pannedHorizontal`（协程内普通 var，不进 Compose 状态）；
  松手时 `repinPriceRange(frozenBase)` 把手势期间的**显示量程**（`frozenBase.scaled(priceZoom).panned(pricePan)`）
  反算成相对新窗口的意图 ⇒ 取景原地不动。
  - 坑：一开始直接拿 `priceBase`（冻结的**基准**）去反算，松手反而变成了自动适配（截图可见刻度变窄）——
    显示量程是基准叠加 zoom/pan 之后的结果，必须回放一次。
  - 例外：新窗口数据与冻结量程的重叠 < 25%（`overlapShare`）时不钉，交给自动量程重排，
    否则会得到一张空图。
  - 只对横向平移生效；捏合缩放仍是「手势冻结 + 松手一次性适配」。
- 想回到自动适配：左下角「刻度已缩放 · 复位」（只清纵向，保留横向视窗）。

### 验证

- `:app:testDebugUnitTest` **394 例 0 失败**（`ChartViewportTest` 新增 4 条：意图回放逐值相等 / 基准不变时
  意图仍是 `(1, 0)` / 退化入参返回 null / 重叠比例 100%·50%·0%·退化四格）。
- MuMu 实测：拖动中与松手后两帧逐像素一致（K 线、刻度、虚线位置都不动）；第二次拖动也不再在按下瞬间跳。
- MuMu 环境注意：`input motionevent` 偶发 `SecurityException: INJECT_EVENTS`，改用 `input swipe`（可后台起、
  中途 `screencap`）即可；本机还有个「绘制位置与 uiautomator bounds 纵向差 ~240px」的怪象，点击验证别信截图坐标。

## K 线：退出详情再进来回到最新一根（Android）

用户：「我往前翻查看 K 线历史，退出详情重进，应该回到最新 k 线」。

- 根因：`AppSettings.chartRightOffset`（DataStore `chart_right_offset`）把横向右端位置也落了盘，
  `restoreChartPreferences` 原样恢复；详情页的 ViewModel 挂在 NavBackStackEntry 上，pop 即销毁，
  再进来就是一次重新恢复 ⇒ 又回到上次看的历史位置。
- 改法：**横向位置不再落盘**（宽度 `visibleBars` 与纵向 `priceZoom/pricePan` 仍跨会话）。
  - `AppSettings` / `SettingsDataStore` 删字段与键（老装机残留的 `chart_right_offset` 直接忽略）；
  - `commitChartView` 只写宽度 + 纵向三数；
  - `restoreChartPreferences` 用 `ChartViewport(saved.chartVisibleBars, ChartViewport.DEFAULT_RIGHT_BLANK)`。
  - 本页内不受影响：切周期、竖屏↔全屏交接、旋屏（ViewModel 存活）仍用内存里的 `ChartViewState`。
- 决策记录补在 `android/basedata/2026-10-03_视角持久化_全局看图习惯.md` 第五节（旧文档原本写「右端停哪也持久」）。
- 验证：MuMu 实测 —— 30 分钟图拖到 10-24 10:00 → 返回行情 → 重进详情，右端回到 10-26 最新一根；
  `:app:testDebugUnitTest` 394 例 0 失败。


## K 线：横向拖动不重排纵轴（桌面端，同日补齐）

用户：「桌面端也存在同样问题，修复」。桌面端没有「手势结束才重排」的突变，而是**拖动全程逐帧重排**：
`draw()` 每帧都拿当前窗口的 `mainRange(ws, we)` 当纵向基准 ⇒ 拖过价格区间边界时网格线整组跳一次
（实测 14 帧里换了 3 次行号）。

- `KlineCanvas.tsx`：`pointerdown` 进入拖拽时把自动量程冻结进 `panBaseRef`，`draw()` 用
  `panBaseRef.current ?? mainRange(...)` 当基准；`endDrag` 里 `axis === 'H'` 时 `repinPriceAfterPan(frozenBase)`
  把**显示量程**（`priceRange(frozenBase, priceRef)`）反算成相对新窗口的意图并落盘 ⇒ 拖动中与松手后都不动。
- `chartMath.ts`：新增 `priceIntentFor(target, base)` / `overlapShare(a, b)`，导出 `PRICE_MIN_VISIBLE_SHARE`
  （与 App `ValueRange.intentFor` / `overlapShare` 同口径）。重叠 < 25% 时不钉、退回自动适配。
- 桌面端语义保留：横向视窗仍全局持久化（没有详情页出/入这一说），双击复位两者都清、小标只清纵向。
- 验证：纯函数 30 条（`check-chart-pan-pin.mjs`）+ 无头 Chrome 真拖动 9/9（`verify-chart-pan-pin.mjs`）。
  判据用**主图网格线行号**，不哈希右轴刻度（「最新价」牌随行情跳字会污染）；旧行为对照 3 种行号 vs 新行为 13 帧恒定。
  `tsc --noEmit` / `npm run build` 绿。

## 双端缩放记忆 + 复位口径统一（同日第四次，未发版）

用户：「双端切换周期、重开详情应该记住横纵坐标的缩放，复位可以恢复横纵坐标的缩放且回到最新价，重开详情只能回到最新价」。

- 口径：横向缩放 visibleBars + 纵向 priceZoom 跨周期/重开详情/重启都保留；横向位置 rightOffset 不落盘，重开详情（桌面=换标的）回 DEFAULT_RIGHT_BLANK；切周期纵向只重定 pan 到现价、倍数不动；「复位」（小标/桌面双击）= ChartViewport.initial()/initialViewport() + 纵向 1/0 + 落盘。
- 复位小标判据扩成「纵向调过 || 横向不是默认取景」：App `ChartViewport.isInitial()`、桌面 `chartMath.viewportAdjusted()`（容差 1e-3 根）。
- 桌面：`chartViewPrefs.ts` 重写，存档只有 visibleBars/priceZoom/pricePan（老存档 rightOffset 忽略）；KlineCanvas 的 `resetKey` prop 拆成 `symbolKey`（market|symbol）+ 已有 `interval`，换标的才拉回最新价；recenter effect 从「重算 zoom 罩住全部蜡烛」改为 `pricePanCenteringOn(base, close, zoom)`（新函数，同 App `ValueRange.panCenteringOn`）——旧实现切周期会抹掉纵向缩放。
- App：KlineChart 复位小标 onClick 改为 viewport = ChartViewport.initial()，亮起条件加 `!viewport.isInitial()`；ViewModel 原有 restoreChartPreferences 已满足「重开只回最新价」。
- 验证：desktop `tsc --noEmit` 绿；`.workbuddy/tmp/check-chart-view-memory.mjs` 13/13（新）、`check-chart-pan-pin.mjs` 30/30；Android `ChartViewportTest` 15/15（+1 isInitial）。未做真机/无头 Chrome 实测。
