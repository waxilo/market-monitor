## 追加：第 5 条「悬浮窗按条数自撑高度」其实一直没生效（同日修复）

上面 `verify-desktop-ui.mjs` 的「1 条 = 34px / 8 条 = 162px」量的是 **CSS 渲染出来的面板**；
真应用里的**窗口高度从头到尾都停在 162**（= 预建值）。第 5 条需求等于没落地。

### 怎么发现的
`smoke-desktop.py` 用 Win32 枚举真实窗口几何。把封顶行数临时改成 2（窗口应缩到 66）—— 窗口没动。

### 两个独立的原因
1. **隐藏窗口量不到排版**：悬浮窗是启动时预建的隐藏窗口，WebView2 不给它排版，
   `getBoundingClientRect()` 恒为 0；`getComputedStyle(el).getPropertyValue('--mini-row-h')`
   同样读不到值 ⇒ `predictedHeight()` 退化成兜底 (32, 5) ⇒ 算出 162 ⇒ 与预建高度相同
   ⇒ Rust 侧 `target == size.height` 直接 return，**静默无变化**。所以从外面看「像是对的」。
2. **`build()` 返回时窗口已经可见**：诊断抓到 `[built] ... vis=true`、位置是系统默认的 (49,49) 物理像素。
   即 `create_mini` 里 post-hoc 的 `set_position` / `hide` 会留下一段「可见 + 位置错」的窗口期，
   前端若在那段里上报高度就会拿错坐标当基线。之前冒烟看到的 `vis=1 at 25,25` 就是这个瞬时态
   （25 vs 49 差一个 DPI 缩放：脚本自己不是 DPI 感知的）。

### 修法（重构式）
- 前端**只报条数**（新命令 `set_mini_rows`），高度在 Rust 算：`rows.clamp(1, MINI_MAX_ROWS) * MINI_ROW_H
  + MINI_CHROME_H`。条数不需要排版也不需要样式，隐藏状态下必然可算。
  删掉了 `predictedHeight` / `panelRef` / `ResizeObserver`；`set_mini_height` 不再存在。
  CSS 变量仍是视觉侧出处（`--mini-row-h` / `--mini-max-rows`），两边常量注释互相点名。
- `create_mini` 改成 builder `.position(x, y)` + `.visible(false)`，位置与可见性一次到位；
  新增 `mini_anchor()` 逐级回退（主窗所在屏 → 主显示器 → 任意屏 → 固定边距），**任何一级都不返回 None**。
- `set_mini_rows` 里 `outer_position()` 报错或给出退化值 (0,0) 时不拿它当锚点，退回监视器右下角。

### 发布动作
`npx.cmd --yes @tauri-apps/cli@^2 build`（**项目没装 CLI，裸 `npx tauri` 会失败**）→ 出 NSIS + MSI →
Python 算 SHA-256 写纯十六进制边车（`newline=''` 防 CRLF）→ `gh release create desktop-v0.1.0` 上传
`-setup.exe` + `.sha256`（MSI 不上传：应用侧 `pick_asset` 只认 `-setup.exe`）。

### ❗双端共库的一个结构性事实
GitHub 的 `/releases/latest` 取「**最新创建**的非 draft、非预发布」⇒ 发完桌面端它就不再指向 Android 包。
实测确认：`gh api repos/.../releases/latest` 现在返回 `desktop-v0.1.0`。
- Android 侧 `VersionCompare.parse("desktop-v0.1.0")`：`removePrefix("v")` 不生效（以 `d` 开头），
  `-` 后半段被当预发布，`parts = ["desktop"]` 非纯数字 ⇒ **返回 null** ⇒ `hasUpdate` 判「无更新」。
  所以**不误弹提示、不装错包，但那段窗口期 Android 收不到更新提示**（直到下次 Android 发版把 latest 抢回来）。
- 桌面端不受影响：`resolve()` 拉 `releases?per_page=100` 再筛 `desktop-v` 前缀，天然免疫。
- 想彻底解耦就让 Android 也「拉列表筛裸版本号」（本次没做，用户选的是只发桌面端）。
- 已验证 `desktop-v0.1.0` **不匹配** `v*` / `[0-9]*` ⇒ 没误触发 Android 的 `release.yml`
  （`gh run list` 里只有 push 触发的 CI）。
