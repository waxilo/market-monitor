## 系统划线（PriceLine.origin）+ EMA 分析面板回显（桌面端）

- `PriceLine` 新增隐藏字段 `origin?: { kind: 'ema'; interval; period }`；**字段缺失 = 用户划线** —— 右键画的老线全在这一类，所以判断一律 `line.origin == null`，没有 `origin:'user'` 这种显式取值（那会给每条老线补一次字段）。`parseOrigin` 认不出的 kind / 非法 period 一律降级成用户划线。
- EMA 面板「点一行」的语义重写：旧逻辑是 `emaAlertAction` 按**精确价**加/取消告警线，病灶是 EMA 每分钟都在动、线停在画它的那一刻 ⇒ 再点就按新价**叠第二条**，两条都画着、面板还看不出自己画过。现在是 `applyEmaLine` 四态：`add` / `align`（漂了拉回当前值）/ `adopt`（这个价上已有手画线 → 收编而不是新增）/ `remove`（已对齐且开告警 → 删）。已对齐但告警被关掉时走 `align`（先恢复告警），不是直接删。
- 回显 = `findEmaLine`：**两遍扫，身份优先、备注兜底**。老存档只有自动备注（`1时EMA50`，`emaAlertNote(intervalLabel, period)` 生成），按它认领并在下一次点击时补上 origin。必须两遍 —— 老线一定排在前面（先画的），一遍扫会永远撞上它、带身份的那条永远轮不到。
- 面板 UI：行尾徽标 `已画` / `待对齐`（`.ema-mark`，已画用 `--down`、待对齐 `--muted` + 左红条淡到 0.4 透明度）；列头 `已画 N`（`.ema-col-marked`）；行 title 写清「图上已画线「备注」= 价位，偏离 x%，再点一下删掉 / 点一下对齐到 y」。`.ema-row` 的 grid 从 5 列改成**固定 6 列**（末列给徽标），没有徽标的行留空才能保证各行价位纵向对齐。
- 兜底一句 `.ema-note`：**孤儿系统线** —— `origin` 的 (周期, 档位) 不在当前 intervals×periods 配置里（用户删过 EMA 目录/周期条），这类线配不上任何一行，不点一句出来用户就只能在图上看见一条红线、面板里怎么也找不到。判据用**配置**不是 `scan.levels`（某档这次没取到数不代表被删）。
- `useDrawings` 新增 `setPriceLines(lines)`（整体替换当前标的线表）：一次点击要同时改价位 + 告警 + 来源 + 备注，逐条调接口会落中间态存档。面板是这条路唯一写入口，两下点击之间隔着一次渲染，所以不会读到上一帧线表。`setLineNote` / `setLineOrigin` 统一走 `withLineFields`，保证改备注不丢 origin。
- 拖动（`movePriceLine`）保留 origin ⇒ 拖过的系统线在面板里显示「待对齐」，点一下即归位。**这是有意的取舍**：一条绑了身份的线，点它就是要它回到该在的价；想要「另画一条」得用右键菜单。

## App 端划线交互改口径：全屏默认不锁 + 「单击选中再拖」（Android）

- 全屏 `linesLocked` 初值 `true` → **`false`**（2026-10-24 用户要求）。配套：`toolHint` 的 `DrawTool.NONE` 那一档原先默认锁定时不显示，现在默认解锁会常驻 —— 改成**图上一根线都没有时返回 null**，有划线才提示（否则每次进全屏都挂一条横幅，横屏空间紧）。文案：「点线选中再按住拖动 · 点空白取消 · 拖到竖栏松手删除」。

- 选中态 `selectedLine` 挂在 KlineChart 内部（`remember(symbolKey, interval.storageKey)`）：上锁、切工具由 `LaunchedEffect` 清空，三个删除出口（拖到竖栏 / 删除工具 / 画线删除）顺手清掉。**没提升到 DetailScreen** —— 提示条要读它就得改成受控参数，代价大于收益（高亮本身就是回执）。
- 高亮 = **同色半透明外发光**（`LINE_SELECTED_HALO_ALPHA = 0.22f` / `LINE_SELECTED_HALO_WIDTH = 9f`）+ 线段加粗；直线两端锚点圆点 ×1.7。不换色：红/黄本身是语义（会响 / 用户记号），不能被临时状态借走。
- ❗**抓已有线时不能在 down 发首帧**：原来 `if (horizontalActive)` 无条件发 `onHorizontalDrag(grab, downY)`，而「选中后点一下线」会走 Drag 通道 ⇒ 线价位被设成手指所在处（抓取容差 24dp，最多偏 72px），松手还 commit 落库 —— 表现为「点一下线，线自己跳了一格」。改成 `if (horizontalActive && horizontalGrab == null)`（只给落空新建发），拖已有线从**第一帧 MOVE** 起算。
- ❗**`grabOffsetY`**：抓取半径 24dp，手指未必正落线上。down 时记「线 y − 手指 y」，每帧落点 = `y + grabOffsetY` 再夹进绘图区，线只跟位移走、不往指尖跳。
- ❗**快速滑一帧会漏判**：循环里 `pendingSelect` / `tapOnBlank` 的作废判定用的是**上一帧**的 `travelled`（累加在循环末尾），「一帧 MOVE 就抬手」的快速滑动会漏判 ⇒ 被当成点击选中。收尾必须再用最终 `travelled` 判一次（`travelled > touchSlop -> Unit`）。

## MuMu 真机验收（同日补做）—— 上面「起不来」那条要收窄理解

- ⚠️ **订正**：沙箱里 `MuMuManager launch` 起不来是真的，但**用户手动启动后完全可连**。所以那条不是「本机没法验收」，而是「**沙箱不能替用户启动模拟器**」——以后遇到同样情况直接请用户启动，不要重试命令、也不要下「无法真机验收」的结论。
- 连法：`MuMuManager.exe info -v 0` 读 `adb_port`（本机是 **16385**，不是记忆里旧写的 16384；同一实例还会以 `emulator-5554` 出现，但那个常 offline，**用 TCP 那条**）。
- ❗**每次 Bash 调用 adb server 都会重启**（输出恒有 `daemon not running; starting now`），上一轮的 `adb connect` 全部失效。所以 **connect 必须和后续操作写在同一条命令里**（`adb connect 127.0.0.1:16385 >/dev/null 2>&1; S=127.0.0.1:16385; ...`），不要跨调用依赖连接状态。
- ❗**`adb shell cat` 不是二进制安全的**（pty 会把换行改掉，导出的 db 字节数对不上，1097728 → 1100318）。导库一律 `adb exec-out "run-as <pkg> cat databases/x.db"`；WAL 模式要连 `-wal` / `-shm` 一起拉，用 Python `sqlite3` 打开才能读到最新提交。
- 竖栏按钮的 `content-desc` 就够定位（`锁定/解锁划线编辑` / `预警线` / `水平线` / `直线` / `删除` / `清空全部划线`），本机横屏坐标：锁 (1857,259)、预警 (1857,351)、水平 (1857,435)、直线 (1857,526)、删除 (1857,618)、清空 (1857,732)。
- 「清空全部划线」有**二次确认框**（`ClearAllLinesDialog`，按钮在 (1281,699)）：直接点竖栏不会立刻清，后续 tap 会被遮罩吞掉 —— 我第一次就卡在这，表现为「清空没生效 + 新线没画上」。

## App 端复刻 EMA 压力支撑分析（Android）

三层落地：`domain/indicator/EmaAnalysis.kt`（纯逻辑，22 条单测）+ `DetailViewModel`（扫描/静默合并/定时器/点击动作）+ `ui/detail/EmaAnalysisSheet.kt`（Dialog 面板）。入口是指标栏里 `＋` 之后、`BOLL` 之前的 `EMA分析` chip（compact 与竖排两个分支都加了）。

**两端结构性差异（决定了回显只能靠名字）**：桌面端系统划线是带 `origin` 的独立实体（`PriceLine`）；Android 的线由 `alert_rule` 派生（一条规则 = 一条线），规则表**没有 (周期, 档位) 的结构化身份字段** ⇒ 回显只能认**规则名**。自动名（`8hEMA50` 这种）是 (周期, 档位) 的双射，所以够用，不必改表。

**不做 adopt（收编）**：桌面端会把同价的手画线收编成系统线；Android 的告警规则是会响、会推送、可能挂 Webhook 的真资产，悄悄改名成 `1hEMA50` 比多一条重合线糟得多。且 EMA 带小数，精确撞上手建阈值概率约等于零。

**EMA 原值不对齐 tickSize**（与桌面端数值一致）：一旦四舍五入，「已对齐」判据永远不成立，面板会满屏「待对齐」；且 `alert_rule` 表本身不校验刻度（校验只在预警编辑器里）。

**取数口径**：每档下限 300 / 上限 1000 根（与图上 300 根历史对齐）；算不出的一律不进表（NaN 会毁掉排序）；`merge` 静默刷新 —— 取数失败沿用旧值并记 `stale`，根数不够也沿用并从 `missing` 划掉，只认当前配置范围。

**真机验收 8 项全过（MuMu，截图 `e6-*` / `e7-*` / `e8-a`）**：表与分档（压力倒序 / 现价分隔线 / 支撑正序）✓、Add（`已画` + 列头 `已画 1` + 浮层回执）✓、Align（`待对齐` → 点一下 → `已对齐 8hEMA50 到 82417.68`）✓、Remove（`已取消`，DB `alert_rule` 清空）✓、周期小方框切周期并关面板 ✓、每分钟自动刷新（`上次 11:02:45` → `11:04:45`，整表数值刷新）✓、横屏两列（压力 17 / 支撑 10 各滚各的）✓、竖屏单列能一路滚到底看到支撑区 ✓。

三个必须记住的 UI 坑：

- ❗**提示条不能当 `Column` 的普通子节点**：notice 出现/消失会改变 `LazyColumn` 的高度，列表在那一秒自己挪几行（用户读到「点一下，我正在看的那行跑了」）。改成外层 `Box` + `align(Alignment.BottomCenter)` 浮层；`Banner` 底色只有 7% 透明度，浮起来透出底下文字，得再垫一层 `Surface(color = paper, shape, shadowElevation = 6.dp)`。
- ❗**偏离配色按列取，不按正负号取**：压力列偏离恒为正，交给 `forChange` 会渲染成「涨绿」，与红色列头自相矛盾。压力 `colors.down` / 支撑 `colors.up`。
- ❗**`DialogProperties(decorFitsSystemWindows = false)` 之后状态栏图标会整片消失**：dialog 是新窗口，不继承 Activity 的 `enableEdgeToEdge`，默认用浅色图标画在纸白顶栏上（真机表现为「时间、电量不见了」，很容易误判成「又被裁了」）。在面板里补：
  `SideEffect { (LocalView.current.parent as? DialogWindowProvider)?.window?.let { WindowCompat.getInsetsController(it, view).apply { isAppearanceLightStatusBars = lightBars; isAppearanceLightNavigationBars = lightBars } } }`，`lightBars = colors.paper.luminance() > 0.5f`（不往主题里加 `isDark` 开关）。

其余两条小坑：`IntervalBadge` 用 `clickable` ⇒ Compose 的 48dp 最小触控区会向两侧扩，**行首那段「点整行」的落点会被它吞掉**（点 EMA50 文字旁边会切成 8h 而不是画线）；测试点行请落在价格列。砂箱 `screencap` 在 MuMu 上旋转后仍是 1080×1920 —— 横屏要走 App 自己的全屏看图（`requestedOrientation = LANDSCAPE`），别指望 `settings put system user_rotation`。

## App 端周期短名改中文（`1h → 1时`）

用户口径：周期标签用中文，`1h` 写成 `1时`。落点只有一个 —— `CandleInterval.label`，全 App 的周期字（周期条 chip、EMA 面板行内小方框、列头「最近 X」、预警编辑器/设置里的周期选择、周期条管理对话框的「X 已在周期条上」）都从它出。

- **单位表与桌面端 `intervals.ts` 的 `SHORT_UNIT` 同源**：分 / 时 / 天 / 周 / 月。`humanize` 的顺序必须由粗到细（月 → 周 → 天 → 时 → 分）：`10080` 得先被「周」认走，否则会写成「7 天」；`43200` 同理（月）。
- **`storageKey` / `apiCode` 一个字没动**（`o:8h`），存下来的当前周期、自选、方言请求全不受影响 —— 界面上是「8时」，发出去的还是 `8h`。
- ❗**自动命名 `8hEMA50` 会跟着变成 `8时EMA50`，而它同时是回显的识别键**。不处理的话，升级后用户之前画的线既没有「已画」标记、又会被孤儿提示点名，而提示里让他「改回配置」根本改不回来。所以 `CandleInterval` 留了 `legacyLabel`（旧英文短名）+ `humanizeLegacy`，`EmaAnalysis` 新增 `legacyNote`：`lineOf` 认新名也认旧名，`orphanLineNames` 的「已配置」集合把两种命名都放进去。
- `AUTO_NAME` 正则改成 `^[0-9]+[\p{IsHan}a-zA-Z]+EMA[0-9]+$`（汉字或拉丁字母，两种命名的周期那一半都吃）。
- **迁移路径是「点一下」**：`alignEmaRule` 本来就把 `name = note` 写回，于是老线点一次「待对齐」就顺手改名成中文 —— 不主动扫库改用户的规则名。
- 单测 22 → **24**（新增「周期短名的单位与桌面端同源」「升级前画的线用英文旧名也要认」），全绿。
- 真机验收（截图 `zh-a` ~ `zh-e`）：周期条 `1分/5分/15分/30分/1时/4时/8时/1天`（选中的仍是 8时，说明 storageKey 没变）✓；EMA 面板小方框 `8时/1天/4时/1时/30分/15分` ✓；点一行画出的规则在 DB 里就是 `8时EMA50`、原值未对齐刻度 ✓；把 DB 里那条手工改成 `8hEMA50` 重启后仍显示「已画 1 + 待对齐」、不报孤儿 ✓；再点一下 → DB 名字迁移成 `8时EMA50`、价位更新 ✓（验完已删掉这条测试规则，`alert_rule` 复原为空）。
- 设备上 `/system/bin/sqlite3` 存在，可以直接 `run-as <pkg> sqlite3 databases/x.db "UPDATE ..."` 改一行 —— 比「拉库改完再推回 + 删 WAL」安全得多，以后造数据用这条。

## 全屏划线：删除收敛成「选中 → 编辑栏」，并给线加备注

用户口径（2026-10-24）：「app 全屏下，去掉右侧的常驻垃圾桶，去掉拖动删除逻辑，点击选中划线，
右侧划线栏变为编辑栏，支持备注、删除」。

**删除从三条路收敛成一条**：
- `DrawTool.ERASE` **整档删掉**（枚举值、`eraseHitAt`、`EraseHit` 全部移除），连同 `visibleAlertLines` /
  `visibleDrawLines` / 手势循环里的 ERASE 分支。
- 「拖到右侧竖栏松手即删」整套撤掉：`lineDropToTrailingRail` / `onLineDropDelete` / `atDropTarget` /
  `droppedOnTrash` 全删。**顺带发现死代码**：`lastRawX`（原始 x）只服务于那个判定，删完没人读，一并清掉。
- 剩下一条：**点线选中 → 竖栏变编辑栏 → 删除**。

**竖栏一副身子两种面孔**：`DrawToolRail(editing, hasNote, onToggleLock, onSelect, onEditNote,
onDeleteLine, onExitEditing, onClear)`。`editing=true` 时是「备注 / 删除 / 分隔 / ✕」，
否则是「预警线 / 水平线 / 直线 / 分隔 / 清空」。`editing` 的唯一来源是 `selectedLine != null`，
不另开模式位。备注那枚在已有备注时用 `colors.accent`（竖栏放不下正文，只能靠颜色说「写过」）。

**选中态要从图表上报到页面**：图表里本来就有 `selectedLine`（管手势归属与高亮），页面还需要它
来决定竖栏长什么样、以及取这条线的 note。加了 `onSelectionChange: (LineRef?) -> Unit`，
图表侧 `val selectionSink by rememberUpdatedState(onSelectionChange)` +
`LaunchedEffect(selectedLine) { selectionSink(selectedLine) }`（`rememberUpdatedState` 是必须的，
否则调用方换了 lambda 这边还捏着旧的）。❗**删除后必须由调用方自己 `selectedLine = null`** ——
线已经没了，图表收不到任何通知，会把一个不存在的 ref 一直举着。

**备注（`note`）与 `alert_rule.name` 必须分家**：`name` 是 EMA 压力支撑面板的认领键
（自动名 `8时EMA50` 是 (周期, 档位) 的双射），拿备注去改 name 会让面板回显全丢 ⇒ 单开一列。
- Room `version = 10 → 11`，`MIGRATION_10_11` 两条 `ALTER TABLE alert_rule / chart_line ADD COLUMN note TEXT`
  （minSdk 26 的 SQLite 支持加列，不整表重建）。两个实体 / 两个领域模型 / 两个 DAO / 两个仓库都加了 `note`。
- 写入走 **只改一列**：`UPDATE ... SET note = :note WHERE id = :id`（`AlertDao.setNote` /
  `ChartLineDao.setNote`）。不要走整行 upsert —— 那是「读出→写回」，会把图表刚拖到的价位盖回旧值，
  也会在调用方没拿全字段时抹掉重复模式 / Webhook。
- `dragDrawLine` 透传 `note = existing?.note`，否则拖一下价位就把备注抹了（验收里专门测了这条）。
- 弹窗 `LineNoteDialog`：`BasicTextField` + 占位「比如「周线压力，跌破转支撑」」+ 字数 `n / 60`，
  留空 = 删掉备注；备注**不上图**（常驻文字牌会跟着线飘、盖住 K 线）。

**真机验收（MuMu 127.0.0.1:16385，`edit-0-*` ~ `edit-27-*`）全部通过**：

  「右侧可以给这条线写备注或删掉它 · 点空白退出」✓

**两条输入注入的坑（会误判成功能坏了）**：
- ❗`input swipe x y x y <ms>`（起止同坐标）**被当成 tap、且不发 MOVE 帧**。长按判定写在事件循环里
  （`held >= longPressMs && travelled <= touchSlop`），没有 MOVE 就永远轮不到它 ⇒ 十字光标「按不出来」。
  带 1–2px 位移（`input swipe 800 400 802 401 1500`）立刻正常（价格标 87317.62 + 日期标「10-23 08:00」）。
- ❗直线**必须用「拖动」画**：纯 tap 一场是 `SEED`（准星不动），第二下 tap 的落点与种子重合 ⇒
  恒判「太近」→ 撤销，而且撤销会顺手把工具收成 `NONE`。所以「点两下」永远画不出直线。
