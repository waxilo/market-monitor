# 双指缩放只走一个轴（禁止叠加）

日期：2026-09-21
涉及版本：0.9.4（versionCode 16）
改动文件：

- `ui/chart/KlineChart.kt`
- `ui/chart/ChartModelTest.kt`（+1 项单测）

需求原文：

> 绘图区只允许单向缩放，不允许叠加缩放，要么左右要么上下，改完发新版本

---

## 一、为什么不能叠加

0.9.3 让横向间距驱动时间轴、纵向间距驱动价格量程，两个维度「各算各的因子」。逻辑上解耦了，但**实际同时生效**：上下拉开时手指不可能保持完全垂直对齐，总会带出一点横向间距变化，于是时间轴也跟着缩。两个轴一起动，用户根本控制不住 —— 这就是「无论上下拉还是左右拉，动的都是横坐标」的老毛病换个形式回来。

## 二、改法：和单指一样先定轴再锁死

```kotlin
val dx = abs(pressed[0].position.x - pressed[1].position.x)
val dy = abs(pressed[0].position.y - pressed[1].position.y)
if (previousDistanceX > 0f && previousDistanceY > 0f) {
    zoomAccumX += dx - previousDistanceX
    zoomAccumY += dy - previousDistanceY
    if (zoomAxis == null) {
        val onPlot = pressed.all { it.position.x < plot.plotWidthPx }
        val locked = ChartGesture.axisLock(zoomAccumX, zoomAccumY, ZOOM_LOCK_PX)
        // 纵向缩放只在两指都落在绘图区时可用；刻度区里的捏合只能是横向
        zoomAxis = if (locked == ChartGesture.Axis.VERTICAL && !onPlot) {
            ChartGesture.Axis.HORIZONTAL
        } else {
            locked
        }
    }
    when (zoomAxis) {
        ChartGesture.Axis.HORIZONTAL -> /* pinchFactor(dx) → onZoom */
        ChartGesture.Axis.VERTICAL   -> /* pinchFactor(dy) → onPriceZoom */
        null -> Unit
    }
}
```

复用单指那套 `ChartGesture.axisLock`：两个维度的**间距变化量**各自累积，谁先够阈值就锁定谁，整场手势只缩放那一个轴。定性之前一个轴都不缩放（首帧只建立基准）。

新增 `ZOOM_LOCK_PX = 16f`，比单指的 `DIRECTION_LOCK_PX = 12f` 略大：两指落下的位置本身就有抖动，阈值太小会在手指还没真正拉开时就把轴定死。

## 三、顺带修掉的一处基准污染

指头数一变（1↔2），旧的两指间距与已定性的缩放轴都失去意义。原先只在单指分支清间距，改成在循环开头按 `pointerCount` 变化统一处理：

```kotlin
if (pressed.size != pointerCount) {
    pointerCount = pressed.size
    previousDistanceX = 0f; previousDistanceY = 0f
    zoomAxis = null; zoomAccumX = 0f; zoomAccumY = 0f
}
```

否则从双指抬成单指、再按下第二根时，会拿上一场的旧间距算出因子，缩放瞬间跳一大格。

## 四、验证（模拟器实测）

用 `sendevent` 注入协议 B 多点触控。两个用例都刻意让**两个维度的间距同时变化**，用来区分「锁一个轴」与「叠加」：

| 用例 | 间距变化 | 结果 |
| --- | --- | --- |
| 纵向主导 | dx 400 → 200（收窄一半），dy 200 → 500 | 价格刻度步长 **2000 → 1000**、K 线纵向放大；时间轴保持 `09-16 14:00 / 09-19 22:00` **纹丝不动** ✅ |
| 横向主导 | dx 400 → 700，dy 200 → 100（收窄一半） | 时间轴 `09-16 14:00 / 09-19 22:00` → `09-17 00:00 / 09-19 20:00`；价格刻度保持步长 **1000 未变** ✅ |

若仍是叠加，纵向主导那一场的时间轴会被放大 2 倍、横向主导那一场的价格量程会被放大 2 倍 —— 都没有发生。

单测：新增 1 项（按间距变化量定轴、变化量大者胜出、都没够阈值则不定轴），全量 **191 项全绿**。

## 五、遗留

时间轴缩放仍是离散的（可见根数是整数根，`accumulatePinch` 每帧最多提交一根），缓慢捏合时是一根一根地跳。根治需把 `ChartViewport` 的 `visibleBars` / `rightOffset` 改为浮点，牵动渲染与全部视窗单测，本次未做。
