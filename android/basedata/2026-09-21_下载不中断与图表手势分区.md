# 下载不被打断 · 图表手势按区域分工 · 切周期后可拖动

日期：2026-09-21
涉及版本：0.9.1（versionCode 13）
改动文件：

- `data/repository/UpdateDownloader.kt`（删除）

- `ui/chart/ChartGesture.kt`

需求原文：

> 1.点击下载期间，我切换页面会打断下载
> 2.图表进行调整，无论是上下拉伸还是左右拉伸，控制的都是横坐标。纵坐标通过拖动价格刻度来实现，向上拖动拉升，向下拖动收缩
> 3.只有从条目进入查看的图表才能拖动，而切换周期的图表固定死无法拖动

澄清后确认的语义：

- 问题 2「向上拖动拉升」= **向上拖 = K 线纵向变高**（量程变小，看得更细），向下拖 = 纵向压缩变矮；
- 绘图区（非刻度区）内的单指上下拖动 = **保留原有的价格平移**（看更高 / 更低价区）。

## 一、下载被切页面打断

### 根因

`SettingsViewModel.downloadUpdate()` 跑在 `viewModelScope` 里。离开设置页 → 该导航目的地的 ViewModel 被 clear → **协程连同正在进行的 OkHttp 请求一起取消**，`cache/updates/` 里只留半个文件。

### 改法

把「检查更新 + 下载 + 安装引导」整体提到应用级作用域，新建 `UpdateCenter`：

```kotlin
class UpdateCenter(
    private val repository: UpdateRepository,
    private val installer: ApkInstaller,
    private val dir: File,
    private val scope: CoroutineScope,   // = AppContainer.appScope
) {
    private val backing = MutableStateFlow(UpdateState())
    val state: StateFlow<UpdateState> = backing.asStateFlow()
    ...
}
```

`UpdateState` 装的是**一次更新会话的全部状态**：`info`（检查结果）、`checking`、`progress`、`apk`、`error`、`needInstallPermission`。

两个关键决定：

1. **检查与下载必须同生共死**。换了版本（`info` 变了），上一轮下好的包就不能再装 —— 把 `info` 和 `apk` 放在同一个不可变状态里，一起被替换，不会出现「卡片写着 0.9.1、装的却是 0.9.0」。
2. **`info` 也必须放应用级**。这是实测中发现的衍生缺陷：只把下载放应用级时，切回设置页会**整张「发现新版本」卡片消失**（`info` 是 ViewModel 的字段，新 ViewModel 拿不到），用户会以为下载丢了。

`SettingsViewModel` 退化成纯镜像：init 里订阅 `container.updateCenter.state`，三个方法体各自单行委托。

### 踩到的坑：初始化时整体覆盖状态

镜像订阅上线后实测**卡片依然消失**。原因是 init 里两个 `viewModelScope.launch` 的执行顺序：

```kotlin
// ① 读 DataStore（慢），读完整体覆盖
backing.value = SettingsUiState(themeMode = ..., ...)
// ② 订阅 StateFlow（立即回放当前值），填更新字段
container.updateCenter.state.collect { ... backing.update { it.copy(updateInfo = ...) } }
```

`StateFlow` 订阅**立即**回放当前值，而 DataStore 读取是挂起的、必然后到 —— 于是 ② 填进去的更新字段被 ① 整体覆盖成 `null`。改成 ① 只 `copy` 设置类字段：

```kotlin
backing.update { s ->
    s.copy(themeMode = it.themeMode, quoteAsset = it.quoteAsset, /* ...仅设置类字段 */)
}
```

**教训**：一个 `MutableStateFlow` 由多个来源分头写入时，任何一方都不能整体赋值，只能 `update { it.copy(...) }` 自己负责的那部分字段。

## 二、手势按「手指起点所在区域」分工

### 根因

双指分支原先同时用横向间距变化（`dx`）和纵向间距变化（`dy`）驱动缩放。但两指的 x 间距**必然**跟着纵向张合一起变，纵向分量永远被横向带偏 —— 用户上下捏合，改的却是横坐标。

### 改法

1. **双指只缩放时间轴**：分支里删掉纵向分量（连同 `previousDistanceY` 变量），只保留 `dx → onZoom`。
2. **纵轴缩放交给「起点落在价格刻度区」的单指纵向拖动**：

```kotlin
// 按下时就定性，整场手势不再改 —— 按主方向判会让同一段位移的语义随手指抖动切换
val onPriceAxis = first.position.x >= geo().plotWidthPx
```

3. 新增纯函数 `ChartGesture.priceScaleFactor(deltaY, plotHeightPx)`：

```kotlin
fun priceScaleFactor(deltaY: Float, plotHeightPx: Float): Float? {
    if (plotHeightPx <= 0f || !plotHeightPx.isFinite() || !deltaY.isFinite()) return null
    return exp((deltaY / plotHeightPx).coerceIn(-1f, 1f))
}
```

取**指数**而非线性映射：每帧位移都很小，指数映射保证「拖过的总距离」与「缩放倍数」是乘性一一对应的 —— 分十帧拖 100px 与一帧拖 100px 结果完全相同；线性映射在跨越钳制边界时会丢掉已走过的行程。单帧因子钳在 `[1/e, e]`，防止异常上报（多指切换、坐标系跳变）让图瞬间缩放几十倍。

因子语义与既有 `ValueRange.scaled()` 一致：**< 1 = 量程变小 = K 线变高**，所以向上拖（`deltaY < 0`）得到 < 1 的因子，正好是用户要的「向上拖 = 拉升」。

单指纵向分支按区域分流：

```kotlin
ChartGesture.Axis.VERTICAL -> {
    val height = geo().mainHeightPx
    if (height > 0f && abs(deltaY) > 0.1f) {
        if (onPriceAxis) {
            ChartGesture.priceScaleFactor(deltaY, height)?.let(onPriceZoom)
        } else {
            onPricePan(deltaY / height)   // 绘图区：保留平移
        }
    }
}
```

顺带补了横向：`Axis.HORIZONTAL -> if (!onPriceAxis && ...)`，手指按在刻度区横向拖不再平时间轴。

## 三、切周期后图表固定死

### 根因（Compose 闭包捕获陷阱）

视窗状态挂在周期上：

```kotlin
var priceZoom by remember(symbolKey, interval.storageKey) { mutableFloatStateOf(1f) }
// viewport / pricePan / crosshair / barPanRemainder / pinchRemainder 同理
```

换周期 → `remember` 的 key 变化 → **重建 MutableState 实例**，旧实例被丢弃。而手势协程的 key 只有 `alertLineMode`，换周期时它**不重启**，闭包仍然捕获着创建那一刻的委托对象（`by` 委托编译出的局部 `val ...$delegate`）—— 于是手势一直在写**已经被丢弃的旧 state**，渲染读的却是新 state。

这正好解释了现象的不对称：**首次从条目进入时**，`remember` 与 `pointerInput` 在同一帧一起创建，闭包持有的就是当前 state，所以能拖；**切过周期之后**，state 重建而协程没重启，就怎么拖都不动。

### 改法

把标的与周期加进手势协程的 key：

```kotlin
.pointerInput(alertLineMode, symbolKey, interval.storageKey) { ... }
```

这两个值**只由用户点击改变**，不会在手势进行中变化，因此不违反项目既有的「数据驱动的值不能进 key」教训（`barCount`、`candles` 那类会随推送变的绝不能进）。
