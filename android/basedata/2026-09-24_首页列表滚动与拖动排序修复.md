# 2026-09-24 首页列表滚动与拖动排序修复

## 用户反馈

> 首页的列表上下拖拽的效果很差，进行修复，可以使用 MuMu 模拟器进行验证效果

## 根因（MarketScreen.kt）

### 1. 滚动发虚闪烁 —— `animateItem()` 默认淡入

`Modifier.animateItem()` 不传参数时自带 fadeIn/fadeOut（spring MediumLow）。LazyColumn 滚动时每个新进入视口的行都会重放一次淡入，列表看起来发虚、闪烁。

**修复**：`animateItem(fadeInSpec = null, fadeOutSpec = null)` —— 位置动画只服务「换位」，不服务「滚动」。

### 2. 拖动排序异步竞态 —— 逐格落库 + 布局延迟

旧实现越过半格就 `onMove` 落库，链路为 launch → Mutex → Room 事务 → Flow 回流 → 重组，需要数帧；期间 `dragOffset` 已补偿但布局仍是旧顺序，中心点计算错位 → 可能触发反向换位，被拖行来回横跳。逐格落库也是白耗写放大。

**修复**：两层拆分——

- **换位发生在本地**（`orderOverride: List<SymbolId>?`）：越过半格立刻重排显示顺序（`displayRows` = override 优先、缺项按原序补齐），同帧补偿 `dragOffset += info.offset - target.offset`，邻行由 animateItem 的 placement 动画平滑让位；
- **落库只在 dragEnd 一次**：`orderOverride?.indexOf(row.id)` 得最终位置调 `onMove(id, index)`；`LaunchedEffect(rows)` 监听流回顺序与 override 一致时清空本地状态。

关键洞察：**本地乐观顺序不会被 500ms 行情流打回原样**——rows 的顺序只由自选表决定，行情推送只改内容不改序（旧注释「本地重排会被推送打回」的判断是错的）。

## 验证（MuMu 12，emulator-5554 / 127.0.0.1:16384，1080x1920 @480dpi）

- 滚动帧率（gfxinfo reset 前后对比，双向各两次 swipe）：366 帧，deadline janky 0%，p50 17ms / p90 17ms / p95 18ms，满 60fps
- 拖动排序日志（临时 Log.d 验证后已移除）：
  `dragStart BTCDOWN → swap 0→1 → dragEnd order=[ETH, BTCDOWN, ...] → rowsEffect same=true 清 override`，全链路正确
- 重启 app 后顺序持久（move 落库成功，DAO `findAll` 按 `position ASC`）
- 单元测试全绿，编译通过

## 验证插曲（避免重蹈）

- **input swipe 起点必须在列表内**（y ≥ 600）：y=500 落在概览条（PullToRefresh 之外），LazyColumn 收不到事件，表现为"滚动无效"，多次误判为 bug
- **input draganddrop 拖的是按下时命中的行**：重启后顺序已变，y=705 命中的不再是 ETH 而是 BTCDOWN，分析时容易张冠李戴
- PowerShell `>` 重定向会损坏 adb exec-out 的 PNG 二进制，截图须 `screencap /sdcard/x.png` + `adb pull`
- 截图若恰逢换位动画中间态，行位置看似错乱，静止后（约 2s）正确
- gradle 构建需 JDK 17：`$env:JAVA_HOME = "$env:USERPROFILE\.jdks\ms-17.0.19"`；默认 JAVA_HOME 是 Java 8 会失败
- 沙箱会拦截 kotlin daemon 临时文件，构建命令需在沙箱外运行

# 追加：首页市场切换记忆（同日第二次修改）

## 需求

> 我切换现货还是永续合约，需要记录下来，下次我打开应用应该打开上次使用的那个列表

## 实现

`MarketViewModel.selectMarket()` 在切换成功后把选择写回 DataStore 的 `defaultMarket`（已有 key `default_market`，无迁移成本）：

```kotlin
viewModelScope.launch {
    container.settings.edit { it.copy(defaultMarket = target) }
}
```

- 冷启动链路原本就读 `settings.defaultMarket` → `selectMarket()`，写回后自动恢复，无需新增字段
- 设置页没有 defaultMarket 的编辑入口，写回不冲突；语义定义为「上次使用的市场」
- 附带效果：搜索页（SearchViewModel）初始市场也跟随上次选择，行为一致

## 验证（MuMu）

切到永续合约（ETH 永续，Aster 数据源）→ force-stop 重启 → 自动恢复永续合约选中态与列表。

# 追加：长按拖动排序手感重构 + 行情流数据完整性修复（同日第三次修改）

## 用户反馈

> 现在长按排序的效果也很不好，继续优化，参考配置周期的排序效果

## 根因（三层，前两层是"效果很差"的真凶）

### 1. 行情流按报价资产过滤 → 非 USDT 自选行永远缺数据 / 凭空消失（最大元凶）

自选表里混着 **BNBUSDC、XRPTUSD、DOGEFDUSD、ADABNB** 这类非 USDT 报价的交易对，而 `MarketRepositoryImpl.tickers()` 流里有一行：

```kotlin
.filter { it.id.symbol.endsWith(quoteAsset) }   // quote = "USDT"
```

这 4 个标的被整行滤掉：

- 旧版 `watched.mapNotNull { byId[id] }` 让这些行**凭空消失/回归**（BTCDOWN 缺报时同理）——列表行数 ≠ 自选表行数，**拖动落库的 to 索引与 DB position 完全对不上**，排序必然乱；
- 同时 BTCDOWN（杠杆代币）在 24hr ticker 里偶发缺报，行抖动雪上加霜。

**修复**（三处）：

- `MarketRepository.tickers(market, quoteAsset: String? = "USDT")`：quoteAsset 允许 null = 不过滤（搜索页默认值不变）；
- `MarketViewModel` 的 sources 不再依赖 quoteAsset flow，`tickers(market, null)` —— 自选行按 **SymbolId 精确匹配**，天然支持任意报价资产；
- VM 增加 `lastTickers` 缓存最近一次行情：缺报行用最近值兜底，从未有行情的用占位行（price="…"、额"—"），**保证 rows 行数与顺序恒等于自选表**。

### 2. dragOffset 泄漏给所有行 → 拖动中整列表内容平移

```kotlin
dragOffsetY = { dragOffset.floatValue }   // 每行都读同一个悬浮位移！
```

被拖行跟手的位移被无差别传给**每一行**的内容层，拖动中除被拖行外全部行的内容整体平移一行多，露出底下红色「移除」垫层（整屏通红），且 UP 落点可能误触「移除」点击删掉自选。

**修复**：`dragOffsetY = { if (dragging) dragOffset.floatValue else 0f }` —— 悬浮位移只属于被拖行。

### 3. 「移除」垫层常驻组合 → 空槽裸露

红垫层原本始终参与组合（靠不透明内容层盖住）。被拖行内容跟手离开原槽后，垫层从空槽里裸露出来。

**修复**：`if (revealed || swipeOffset.floatValue < 0f)` 才组合垫层——纵向拖动时空槽显示列表底色，横向左滑的露出功能不受影响。

## 排序手感重构（与「配置周期」对话框同款三段式）

- **拖动中悬浮跟手**：被拖行按 dragOffset 直接平移（zIndex 抬高 + washStrong 底色），列表顺序纹丝不动；
- **被越过区间 tween(150) 让位**：dragTo 按拖动量换算槽位（跨整行才算一步），区间内行平移一行让出空位，让位量取相邻槽位实测 offset 差（行高不均也对得齐）；
- **松手才换位 + 一次落库**：本地 orderOverride 一次重排 + `onMove(id, to)` 落库；落位瞬间 shift snap 归零 + placement 动画关一帧（placementSuppressed），防止 animateItem 把行先弹回旧槽再滑一遍。

## 验证（MuMu）

- 临时日志全链路：`dragStart(from) → dragEnd from=0 to=1 off=194 → apply[13 个标的] → moveWatch → rows 回流 size=13 顺序匹配 → override 清空`
- DB 落库：`SELECT symbol, position FROM watchlist` = [ETH(0), BTCDOWN(1), SOLV(2)...]
- force-stop 冷启动：列表恢复拖动后的顺序，13 行全部有行情（含 BNBUSDC 772、XRPTUSD 1.3178、DOGEFDUSD、ADABNB）
- 拖动中截图：被拖行灰底悬浮跟手、SOLV/BNB tween 让位、原槽无红垫层裸露
- 单元测试全绿

## 验证插曲（避免重蹈）

- MuMu 模拟长按拖动：`input motionevent DOWN` → sleep 700ms → 分步 `MOVE` → `UP`；`input draganddrop` 长按判定时灵时不灵，MOVE 分步事件偶有丢帧（off 累计小于几何位移），验证时以换位结果为准
- **UI 显示 ≠ DB/日志时先查滚动位置**：拖动手势会让列表额外滚动约半行，顶部行半藏在概览条下面，极易误判为"丢行/错序"——先滚动回顶再对比
- `run-as` 查库：`run-as pkg sqlite3 db < /data/local/tmp/q.sql`（stdin 重定向）；`run-as pkg sh -c "..."` 在 MuMu 上因挂载视图看不到 databases 目录；SQL 里的引号/分号会被远程 shell 吃掉 → SQL 写入本地文件再 `adb push`
- adb 会偶发 `device offline` 自愈重启，push 前先确认设备在线，否则会查到旧 SQL 文件的结果
