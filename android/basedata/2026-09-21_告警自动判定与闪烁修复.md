# 告警线自动判定方向 · 单次规则自动移除 · 价格闪烁与图表实时性修复

日期：2026-09-21
涉及版本：未发版（工作区改动，versionName 仍为 0.4.0 / versionCode 6）

需求原文：

> 1、全屏时的告警划线，自动判断上破还是下破，不需要人选。同时支持上破的线移到下方，自动转为下破告警
> 2、告警规则的次数到了应该自动移除
> 3、现在列表页和详情页价格变动都会闪烁，去掉闪烁
> 4、现在图标不会实时渲染
> 5、查看图标时可能会卡住无法拖动。切换周期图标也可能会卡住，需要再次切换才能恢复

（第 4、5 条里的「图标」确认为「图表」笔误；第 2 条按「单次触发后自动删除规则」实现。）

---

## 一、告警划线自动判定上破/下破

### 原来的做法与问题

划线后弹 `AlertDraftDialog`，让用户在「上破 / 下破」里点一个再确认。三个毛病：

- 方向本来**由线相对现价的位置唯一决定**，让人再选一次是多余的；
- 线只是画在图上的一条线，和规则**没有绑定** —— 每松一次手就多一条规则，反复微调价位会堆出一串重复预警；
- 想「把上破改成下破」只能删掉重画。

### 实现

`ui/detail/DetailViewModel.kt`：

- 删掉 `alertDraft` / `alertDraftPrice` / `dismissAlertDraft` / `createAlertFromDraft`，以及 `DetailScreen.kt` 里的 `AlertDraftDialog` 与弹窗宿主。
- 新增 `alertLineRuleId: MutableStateFlow<Long?>`：线是规则的**唯一入口**，两者必须绑定。再次拖动同一条线改的是同一条规则，而不是新建一条。
- `commitAlertLine()`：对齐 `tickSize` 后取现价，`aligned >= reference` 即判为上破，反之为下破。方向是**线本身的位置属性**，所以把上破的线拖到现价下方自然就变成下破。
- `referencePrice()`：优先用实时行情（`state.lastPrice`），拿不到（标的未加自选时没有 ticker 推送）就退到图上最后一根蜡烛的收盘价 —— 它本身就是「最近成交价」的另一种表达。
- 改规则时**必须把触发状态清零**（`alerts.saveState(existing.id, AlertState())`）：条件与价位都换了，旧的 `fired` 闸门会让新条件一次都不提醒，`wasSatisfied` 也会把真正的「穿越」边沿吃掉。
- 规则被删（单次触发完毕，或用户在预警列表里删了）时**自动清线** —— 留一条背后什么都没有的线，会让人以为预警还在跑：

```kotlin
viewModelScope.launch {
    alerts.rules().collect { rules ->
        val bound = alertLineRuleId.value ?: return@collect
        if (rules.none { it.id == bound }) clearAlertLine()
    }
}
```

`clearAlertLine()` 是**非破坏性**的：只清线、不删规则。用户可能只是想换个价位重划，顺手删规则会让他在预警列表里白找一场；真正删规则的入口是预警列表。

`DetailScreen.kt` 的全屏提示文案同步改为「上下拖动放置告警线 · 松手按线的位置自动判定上破/下破」。

## 二、单次规则触发后自动移除

`data/alert/AlertEngine.kt`：

- `onTriggered` 返回值从 `Unit` 改为 `Boolean`，末尾追加：单次模式删除规则并返回 `true`。记录（`alerts.record`）、通知、Webhook 都做完才删，避免删库把还没发出去的通知一起带走。
- `evaluateAll` 据此跳过退场规则的状态回写：

```kotlin
val retired = decision is AlertDecision.Triggered && onTriggered(rule, decision)
// 已退场的规则不能再写状态：deleteRule 连状态一起删了，回写等于凭空造出一行孤儿
if (!retired && changed(previous, next)) alerts.saveState(rule.id, next)
```

`EVERY_CROSS` / `REPEAT` 行为不变。

## 三、列表页/详情页价格闪烁

`ui/common/CommonUi.kt` 的 `rememberPriceFlash` 以 `changePercent` 作触发键：ticker 每 500ms 推送一次，动画还没播完就被下一次 `snapTo(1f)` 打断，于是底色在闪烁色与常态之间反复跳。

删掉整个 `rememberPriceFlash` 及 `MarketScreen.TickerRowItem` / `DetailScreen.Hero` 两处调用。列表行的 `.background(colors.paper)` 保留 —— 它是不透明底色，用来盖住左滑后露出的红色「移除」按钮。

## 四、图表不实时渲染

`ui/chart/KlineChart.kt` 的 `ChartLegend`：

```kotlin
// 改前：remember(crosshair, barCount, interval, tickSize)
tooltip = remember(crosshair, series.candles, interval, tickSize) { ... }
```

key 里放的是 `barCount`（根数）。**最新一根蜡烛在收盘前每 tick 都在变（开高低收/量都在动），但根数一直不变** —— 用 `barCount` 当 key 会让图例上的数字整根蜡烛期间冻住，看起来就是「图表不实时」。改成蜡烛数据本身之后，每次 tick 都会重算。

## 五、图表卡住无法拖动 / 切周期后卡住

### 根因

`.pointerInput(...)` 的 key 里含 `barCount`：

```kotlin
.pointerInput(geo.plotWidthPx, geo.mainHeightPx, barCount, alertLineMode)
```

而 `barCount` = `series.size`，**新蜡烛到达、翻页 `loadMore`、切周期都会让它变**。key 一变 Compose 就取消并重启手势协程；手指还按着时，新协程的 `awaitFirstDown` 要等一次全新的按下事件，而它内部用的是 `changedToDownIgnoreConsumed()`（要求「未按下 → 按下」的跳变），手指没抬起就永远等不到。

表现为两种症状，正是用户描述的两条：

- 「切周期后卡住，需要再次切换才能恢复」—— 切换动作重启协程，把当时的手势作废；
- 「查看图表时可能会卡住无法拖动」—— WS 推来一根新蜡烛同样会改 `barCount`。

### 修法

- `pointerInput` 的 key **只留 `alertLineMode`**（划线开关，只由按钮切换，不可能在手势中途变）。
- 其余一切（绘图区几何、根数、序列、自动量程、`onLoadMore`）改走 `rememberUpdatedState`，协程启动后读到的始终是实时值：

```kotlin
val liveGeo by rememberUpdatedState(geo)
val liveBarCount by rememberUpdatedState(barCount)
val liveSeries by rememberUpdatedState(series)
val liveAutoRange by rememberUpdatedState(autoRange)
val liveLoadMore by rememberUpdatedState(onLoadMore)
```

- `detectChartGestures` 的几何入参从三个 `Float` 定值改成 `geo: () -> ChartGeo` 取值函数：尺寸变了协程不会重启，用定值会拿旧尺寸换算落点（旋屏后划线直接跑偏）。

### 单次规则自动移除（问题 2）

上一步的 81286.83 上破线只高于现价 40 USDT，几十秒后价格上穿：

- 状态栏出现预警通知图标；
- 退出全屏后「清除线」chip 消失（线随规则一起清掉）；
- 预警列表显示「**0 条规则**」/「还没有预警规则」。

0 条同时证明划线走的是 **upsert** —— 三次拖动若各建一条，触发只会删掉最后一条，列表里应剩 2 条。

### 图表实时渲染（问题 4）

同一根 10:30 的 15m 蜡烛期间，图例随 tick 变化：

`收 81200.00 / 量 73.25` → `收 81246.57 / 量 87.97` → `收 81260.00 / 量 107.98`

### 拖动与切周期（问题 5）

临时插桩 `Log.d` 抓手势日志（验证后已移除）：

- 竖屏详情页水平拖动：`axis=HORIZONTAL`，`onPan` 每帧回调，`bars=-1/-2` 持续提交，时间轴随动；
- 全屏横屏水平拖动：同样正常，时间轴由 `00:20/02:50/05:20/07:50` 变为 `06:10/08:40`，右侧露出留白；
- 切到 15m 后**立刻**拖动：`onPan` 正常，时间轴跳到 `09-20 04:30 … 09-21 03:00`。

### 排查记录（避免下次重踩）

首次在全屏验证问题 5 时「怎么拖都不动」，一度怀疑是代码缺陷。实际是**测试假象**：误点了「划线」chip 进入划线模式，该模式下单指拖动改为移动告警线而非平移时间轴，所以纵横向都「没反应」。后续定位靠的是在 `detectChartGestures` 里插桩打印每帧的 `pressed.size / deltaX / deltaY / axis` —— 手势逻辑这类问题，日志比截图可靠得多。

另外两个模拟器坑：

- `adb shell input swipe` 的坐标是**当前旋转后的屏幕坐标**，`screencap` 输出的 PNG 尺寸也随之变化（横屏 1920x1080、竖屏 576x1024），截图坐标换算必须按当次实际尺寸来；
- 零距离 swipe（`x1==x2 && y1==y2`）不会产生 MOVE 事件，手势循环收不到任何一帧，划线/拖动都不会触发，必须给一段真实位移。
