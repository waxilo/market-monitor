## 一、加速站从「手填前缀」改成内置下拉（需求 1）

`domain/update/UpdateMirror.kt` 由一个 `apply(url, prefix)` 的工具函数升级为枚举：

```kotlin
enum class UpdateMirror(val key: String, val label: String, val prefix: String, val apiCapable: Boolean)
```

站点是**实测筛出来**的（curl 逐个跑资产下载与 API 中转），活着的进枚举、死掉的直接不列：
`gh-proxy.com`、`ghfast.top`、`ghproxy.net`、`gh-proxy.org`，默认 `NATIVE`（GitHub 原生直连）。
`gh.llkk.cc` / `hub.gitmirror.com` / `github.moeyy.xyz` / `ghp.ci` / `mirror.ghproxy.com` 已停摆。

设置页换成通用 `DropdownRow`（`ui/settings/SettingsScreen.kt`）。没用 M3 的 `ExposedDropdownMenuBox` ——
它自带边框 + 浮动标签，而本页刻意不留边框；也没用分段控件：五家标签长短不一，排一行会挤到看不清。

**DataStore 仍写同一个 key（`update_proxy`）**，只是值从「原始前缀」变成枚举 `key`；
`fromStored()` 两种都认（旧前缀按 `prefix` 反查，末尾斜杠不敏感），这样已装的 0.9.8 升级后不会静默丢掉用户选过的站。

## 二、开 VPN 检查更新 403（需求 2）

不是代理没生效 —— `AppContainer` 早就把系统代理（`ConnectivityManager.defaultProxy` + `http.proxyHost`）套进 OkHttp 了。

真实原因是两件事叠在一起：

1. 旧版的加速前缀**只作用于下载**，`api.github.com` 永远直连；
2. VPN 出口常是共享机房 IP，GitHub 对这类 IP 限频甚至直接 403 —— 而 `github.com` 的资产下载不受同样约束。

于是「下载能成、检查报 403」正好对上。修法：

- 枚举带 `apiCapable` 标记，记录「这家是否中转 `api.github.com`」。实测只有 `gh-proxy.com` 与 `gh-proxy.org` 放开；
  代不了 API 的站放进候选只会白跑一趟，所以**不进 API 候选链**。
- `GithubReleaseApi` 的所有请求改成**候选地址链**依次尝试（`firstOk`）：所选站 → 直连 → 其他可用站。
  加速站随时停摆是这类公益代理的常态（寿命以周计），链上只要有一个通用户就拿到包。
- 403 单独给提示语（`可能被限流或拒绝该出口 IP`），并在多源都失败时附「已依次尝试 N 个源」——
  只报 403 用户不知道该干什么。
- `404` **不**继续换源：文件本来就不存在（发布没带 `.sha256` 边车），换一家还是 404，直接停手让调用方按缺失处理。

## 三、划线模式能看到并调整已有告警（需求 3）

改前只有一条临时线：`alertLine: MutableStateFlow<BigDecimal?>` + `alertLineRuleId: MutableStateFlow<Long?>`，
外加一个「规则没了就清线」的 effect。历史告警在图上根本看不见，更谈不上调整。

改后**线由规则派生**，不再是独立状态：

```kotlin
val alertLines: StateFlow<List<AlertPriceLine>> = combine(alerts.rules(), alertDrag) { rules, drag -> ... }
```

- 过滤本标的 + `threshold != null`（只有上破/下破有单一价位，区间/涨跌幅画不出一条线）。
- 派生而非另存，于是「规则在预警页被删 / 单次触发后被移除」时线自动消失，反方向（在预警页改阈值）也同步 ——
  那个「规则没了就清线」的 effect 直接删掉。
- 只剩 `alertDrag` 一个临时态：手指没抬起时的那根线，`dragging=true` 覆盖掉对应规则的历史价位。

抓取判定放在**图表**里（只有它有像素）：`KlineChart` 收 `List<AlertPriceLine>`，按下那一刻用
`alertAnchors()`（走 `liveGeo` / `liveAlertLines` 实时值）算出各线的 y，`closestAlertLine(y, 24dp)` 决定抓哪根。

两个关键取舍：

1. **抓哪根每场手势只判一次**。逐帧重判的话，把手里的线拖过另一根时会突然「换手」—— 手指没动，
   动的却是另一条预警的阈值。
2. **容差 24dp**。屏幕上那根 1.5dp 的虚线按不准，容差太小会让「微调已有预警」变成「凭空多出一条新预警」。

线**始终绘制**，划线模式只是「能不能拖」的开关：看不见自己设过的预警价、却要先进划线模式才能调，
等于把线藏进抽屉。非拖动的各根压淡到 45% 不透明度 —— 它们是参照物，不该跟 K 线抢视线。

顺带修的隐患：价位与方向都没变时**不再写库**（`upsertAlertLineRule` 直接返回）。否则按住一条已经响过的
「单次」预警再松手，触发状态被清零 → 它会再响一次。原来的单选线不会碰到这个问题（只有绑定的那根能拖），
现在任何一根都能被抓起来，就必须要挡。

## 四、预警消息支持清空（需求 4）

`AlertDao.deleteAllLogs()`（`DELETE FROM alert_log`）→ `AlertRepository.clearMessages()` → 消息页右下角「清空」文字入口 + `AlertDialog` 二次确认。

- **只删记录，不动 `alert_state`**：规则的「已触发/冷却」判定状态与消息列表是两回事，清历史不该让单次预警重新响一遍。
- 确认框文案明说「预警规则不受影响」—— 用户最怕的就是清了历史把预警也清了。
- 不报「共 N 条」：列表只取最近 200 条，报出来的数字会比实际删的少。
- 「清空」做成安静的文字入口而不是第二颗黑胶囊：它不是常规动作，点了还要弹确认，不该跟「标记已读」同权重。

## 五、详情页菜单与全屏入口（需求 5、6）

- 三个点里删掉「重新加载 K 线」：K 线本来就在实时刷新，手动重载只在取数失败时由空状态的按钮提供，日常不需要第二个入口。
- 「全屏」从顶栏搬到**图表左上角角标**（`KlineChart(cornerAction = ChartCornerAction(...))`）：详情页要滚动才看到图表，
  入口钉在顶栏等于每次先把页面翻回去。图标是 `FullscreenGlyph` 用 `Canvas` 画的四条直角边 ——
  `Icons.Default.Fullscreen` 在扩展包里，项目只依赖 `material-icons-core`；而Compose 1.10 起
  `ImageVector.Builder.addPath` 只收 `List<PathNode>`（字符串重载已去掉），手搓矢量不如直接画。
  于是角标内容由调用方给 composable（`ChartCornerAction.content`），无障碍文案挂在按钮节点上。
- 读数带随之右移让位（`readoutStart = Xxs + 32dp + Xs`，可用宽度同幅减掉），否则角标压在 MA 读数上。

## 六、上一轮遗留的两处版面改动（同批提交）

- 全屏的周期条**常驻摊开**放在图表下方：换周期是全屏里最高频的动作，每次先展开再选、选完又收起，连换两个周期要点三次。
- 图上不再常驻 OHLC 那一大块（它常年压着左上那片蜡烛，而左上是近期高点与形态最常待的地方）：
  - 指标改成币安式的一行彩色读数带（`IndicatorReadout`），片段颜色与它所描述的那条折线同色 ——
    「这个数字属于哪条线」由颜色说清，不再需要整块图例；用 `AnnotatedString` 而不是 `Row` + 多个 `Text`，
    因为纯文字不吃指针事件，读数带不会把顶部那一带的手势从图表手里抢走。
  - OHLC 改成只在长按出十字光标时浮在读数带下方，松手即消失。
  - 读数带占用的顶部高度由 `ChartGeo.READOUT_HEIGHT_DP`（34dp）保留，旧 `LEGEND_HEIGHT_DP`（62dp）取消。
