# 行情多域回退不再被裸 404 掐断 · 备用域名设置补上入口

日期：2026-09-22
涉及版本：0.9.10（versionCode 22），上一版 0.9.9 已发布

需求原文：

> 现在这版不连 vpn 无法查看行情，改回去

---

## 一、先确认「这版改坏了什么」——答案是没改坏

0.9.8 → 0.9.9 的行文里，行情链路一行都没动：`BinanceMarketApi.kt`、`MarketType.kt` 逐字节相同，
`AppContainer.kt` 只有更新客户端的 `mirror = { ... }` 那一行。DataStore 的 key 也没有撞车
（`update_proxy_prefix` 与 `spot_rest_mirror`/`futures_rest_mirror`/`ws_mirror` 各自独立），
所以升级不会把用户的镜像设置冲掉。

在一台**没连 VPN** 的机器上实测（结论对大陆网络成立：`api.binance.com` 全族不通）：

| 域名 | 结果 |
| --- | --- |
| `data-api.binance.vision/api/v3/{ping,exchangeInfo,klines,ticker/24hr,depth,trades}` | 全部 200 |
| `data-stream.binance.vision/stream?streams=btcusdt@ticker` | 101 握手成功并持续推帧 |
| `api.binance.com` / `api1~3` / `api-gcp` / `fapi.binance.com` | connect 超时 |

也就是说：现货的内置候选链本来就是免 VPN 可用的，合约则**无论哪一版**都只有 `fapi.binance.com` 一个域，
不连 VPN 必然打不开 —— 这不是回归，是从头到尾的既成事实。所以「改回去」没有可回滚的目标，
真正要做的是把「行情请求不到数据」这件事变得能自救、能自查。

## 二、真正的 bug：镜像回裸 404 会掐断整条候选链

`BinanceMarketApi.get` 原来这么判断：

```kotlin
// 4xx 换域名也没用（参数或标的错误），直接上抛
if (e.httpCode in 400..499 && e.httpCode != 418 && e.httpCode != 429) throw e
```

「4xx = 参数错」这个前提只在**请求真的到了币安**时成立。镜像与 CDN 同样会回裸 404/403：
`data-api.binance.vision/fapi/v1/ping` 实测就是 404（它是现货行情专用域，不服务合约端点）。
于是只要用户在设置里填过一个「看着没错」的镜像域，链路在**第一个**域名就整体抛错，
后面内置的可直连域根本没机会被试 —— 表现正是「不连 VPN 就没有行情」，而且是无法自查的那种。

改法是问「这错误是不是币安亲口说的」：响应体带业务码（`-1121` 标的不存在、`-1003` 限频）才短路，
裸 HTTP 状态码一律继续换域。规则抽成顶层 `shouldTryNextHost(error)`，附单元测试钉住：
裸 404/403/418/429 → 换域；带业务码的 4xx → 直接上抛（每个域名都会给同样答案，继续试只是白烧权重）。

## 三、错误文案说出试过哪些域名

全链失败时原来只丢出「现货请求失败」。现在带上实际试过的域名与最后一个错误：

```
现货行情请求失败：mirror.example.com、data-api.binance.vision、api.binance.com …… 都不可用（HTTP 403）
```

用户对着这一行就能判断是「我填的镜像死了」还是「整个网络到不了币安」，不必再来回猜。

## 四、把三个备用域名设置补上入口

`spotRestMirror` / `futuresRestMirror` / `wsMirror` 早就有存储、有链路、有 DI 接线，
**唯独设置页没有入口** —— 合约用户唯一的自救口子在界面上根本不存在。现在「行情」一节补三行
（逗号分隔、按顺序试、排在内置域之前），并把话说清楚：现货与推送已带大陆可直连的官方域，
一般留空即可；合约官方只公布 `fapi.binance.com`，不通要么走代理要么自填镜像，
而填错不再会连累内置域名。

## 五、没有内置的「可直连合约域名」，这是有意的

`*.binance.com` 在这个网络下连 `qqq.binance.com` 都能解析出污染 IP，探测无法用来判断域名存在。
而合约行情域经第三方中转等于把**价格数据**交给一个来路不明的主机 —— 这个应用拿它判断上破/下破并推送预警，
错一个数字就是一次假警报。所以不往候选链里塞任何没验证过的域名，合约的可直连镜像留给用户自己填。
