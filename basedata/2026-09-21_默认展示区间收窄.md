# 默认展示区间收窄（120 → 60 根）

日期：2026-09-21
涉及版本：0.9.5（versionCode 17）
改动文件：

- `ui/chart/ChartViewport.kt`

需求原文：

> 每个图标的默认展示区间太大了，显得图很小

（「图标」应为「图表」）

---

## 一、改动

`ChartViewport.DEFAULT_VISIBLE` 由 `120` 改为 `60`：

```kotlin
/**
 * 默认可见根数。
 *
 * 取 60 而不是更宽：绘图区宽度约 906px（1080 屏减去 58dp 的价格刻度区），
 * 120 根摊下来每根只有 7.5px、蜡烛实体约 5px，一眼看去整张图又密又小。
 * 60 根每根约 15px，实体宽约 10px，形态看得清，一屏也仍够看出趋势。
 */
const val DEFAULT_VISIBLE = 60
```

这是**初始视窗**的宽度，用户随时可以双指缩放改掉；`clamp(barCount)` 仍会按实际根数收窄，短序列安全。

## 二、排查中确认的另一件事（本次未改）

截图对比时发现 K 线仍挤在绘图区上部 1/4，原因是 `ChartSeries.mainRange` 把叠加指标（MA / BOLL）的值也算进了自动量程：

```kotlin
val withOverlays = overlay.lines.mapNotNull { ValueRange.of(it.values, start, end) }
val all = listOf(base) + withOverlays
return ValueRange(all.minOf { it.low }, all.maxOf { it.high }).padded()
```

BOLL 带张开时量程被撑到 76000~82000，而同期蜡烛只在 80500~81900 —— 蜡烛因此被压扁。

这属于**纵向量程**问题，与横向根数是两回事。经确认用户只要横向收窄，故本次未动；若日后觉得 K 线偏扁，改法是以蜡烛高低点为准、指标超出绘图区的部分裁掉。

## 三、验证

模拟器实测：默认进入 BTC/USDT 1h 详情页，时间轴由 `09-16 14:00 / 09-19 22:00`（约 3.3 天）收窄为 `09-19 03:00 / 09-20 19:00`（约 1.7 天），蜡烛宽度翻倍。

单测：全量 **191 项全绿**（`DEFAULT_VISIBLE` 没有硬编码依赖，无需改测试）。
