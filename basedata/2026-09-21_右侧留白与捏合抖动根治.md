# 右侧默认留白 3 根 + 捏合抖动根治（视窗浮点化）

日期：2026-09-21
改动文件：

- `ui/chart/ChartViewport.kt`（视窗浮点化、新增 `plotStart`、`DEFAULT_RIGHT_BLANK`）
- `ui/chart/ChartGesture.kt`（删掉两个累加器，只留 `barDelta`）
- `ui/chart/KlineChart.kt`（删掉两个余量 state，改传 `PlotGeometry`）
- `ui/chart/ChartModelTest.kt`（同步改写，全量 182 项）

需求原文：

> 1. 最新的蜡烛右侧默认留空 3 根蜡烛的空间
> 2. 左右伸缩时为什么会显得抖动，是否可以优化

---

## 一、需求 1：右侧默认留白 3 根

新增常量并在初始视窗里生效：

```kotlin
/**
 * 初始视窗在最新一根右侧留出的空白根数。
 *
 * 留 3 根：最新一根贴着右边缘时右边没有任何参照，正在走的那根蜡烛
 * 等于压在边框上，看不到它后续还能往哪走；留一点空白既让最新一根
 * 离开边框，也和真实交易软件的默认观感一致。
 */
const val DEFAULT_RIGHT_BLANK = 3f

fun initial(): ChartViewport = ChartViewport(DEFAULT_VISIBLE, DEFAULT_RIGHT_BLANK)
```

几何上「右端 = `barCount - 1 + rightOffset`」，所以末根蜡烛中心距右边界 **3.5 个槽宽**（3 根空白 + 半根实体偏移）。

**顺带堵掉一个边界**：整段序列一屏就放得下时（新币的月线常常只有十几根）不留白 —— 此时屏幕里本就没有多余空间，留白只会把最老的那几根挤出左边界，表现为「少了几根蜡烛」：

```kotlin
val maxOffset = if (barCount <= visible) 0f else maxRightBlank(visible)
```

## 二、需求 2：抖动是怎么来的

### 根因一：可见根数是 `Int`

`zoom()` 里最后一步 `(visibleBars * factor).roundToInt()`。可见 60 根时，缓慢捏合一帧手指只挪 3~5px，折算出的根数变化只有零点几根 —— 取整后**每帧都被抹成 0**，于是「几帧纹丝不动、突然跳一根」。一根就是 15px，肉眼看到的就是横向抖动。

### 根因二：为了救上面这一点而加的限速累加器，本身是第二个抖动源

`accumulatePinch` 把 `ln(factor)` 攒起来、凑够一根才提交，且 `val step = whole.coerceIn(-1, 1)` **每帧最多提交一根**：

- 缓慢捏合 → 攒够一根才跳一次（一根 15px 的台阶）；
- 快速捏合 → 一帧该走 3 根却只走 1 根，画面严重滞后于手指；
- 还配了 `reportApplied` 把 `roundToInt` 的误差退回余量，误差在「攒 → 取整 → 回填」之间来回震荡。

`pan()` 里的 `roundToInt()` + `accumulateBarPan` 是同一套写法，同样的问题。

**结论：累加器是给「整数视窗」打的补丁，补丁本身成了抖动源。根治办法是把视窗改成浮点，然后整块删掉补丁。**

## 三、改法：视窗浮点化

### ChartViewport

- `visibleBars` / `rightOffset` 由 `Int` 改 `Float`；
- `zoom()` / `pan()` 不再取整，锚点公式照旧（`anchor = start + V * ratio`，`O' = newStart + target - barCount`）；
- 新增**浮点左端** `plotStart(barCount): Float = barCount + rightOffset - visibleBars`，供像素定位；
- 整数 `window()` / `plotRange()` 仍返回 `IntRange` 供取数据，两端统一 `floor`（左端把被裁一半的那根纳进来，右端排除完全越界的那根）；
- `fractionOf` / `indexAt` 改用浮点 `span`。

两者分工写进了 `PlotGeometry` 的注释，并有单测钉住「浮点左端取整后与整数窗口两端对齐」，防止渲染与取数脱钩。

### ChartGesture

`accumulatePinch` / `PinchBar` / `reportApplied` / `accumulateBarPan` / `BarPan` 全部删除，只剩一个纯换算：

```kotlin
fun barDelta(pixelDelta: Float, slotPx: Float): Float
```

### KlineChart

- `barPanRemainder` / `pinchRemainder` 两个 state 删除；
- `plotRange` + `visibleBars` 两个 remember 合成一个 `PlotGeometry(indices, start, visibleBars)`，所有 draw 函数签名由 `(window: IntRange, visibleBars: Int)` 改为 `(plot: PlotGeometry)`；
- `ChartGeo.slot(visibleBars: Float)`、`xOf(index, plot)`；
- 手势里不再有「攒够一根才提交」的分支，`viewport = viewport.pan(deltaBars, bars)` / `viewport.zoom(...)` 直接生效。

## 四、验证

### 单测（182 项全绿）

- 新增：`初始视窗在最新一根右侧留三根空白`、`浮点左端取整后与整数窗口两端对齐`、`序列不足一屏时不留白以免挤掉最老的几根`、`连续小位移平移逐帧累积而不是被抹平`、`横向位移折算成小数根而不是取整抹平`、`缓慢捏合的每一帧都连续生效而不是攒够一根才跳`、`单帧的缓慢捏合也会被完整施加`、`捏合的缩放量是精确乘性的与分几帧捏无关`；
- 删除：19 项针对累加器内部状态的测试（`reportApplied` 回填、`coerceIn(-1,1)` 限速、余量守恒等）—— 被测对象已不存在；
- 保留并改写：视口/留白/锚点/边界等既有断言，全部改按 Float 断言。

### 模拟器实测（1080x1920，绘图区 906px）

**需求 1**：默认进入 BTC/USDT 5m 详情页，按蜡烛实体列做自相关，测得槽宽 **15px → 可见 60 根**；末根中心在 x=853，距绘图区右边界 906 为 **53px = 3.5 个槽宽**，即 3 根空白，与设计一致。

**需求 2**：注入双指张开（间距 300 → 600，即 2 倍），终态可见根数 **60 → 31**（理论 30）—— 缩放量与手指行程精确成比例，说明既没有被 `roundToInt` 抹平、也没有被「每帧最多一根」限速拖住。

单指拖动（`input swipe`）同样确认：左拖后末根从 x=853 移到 x=565，右侧留白按预期出现。

> 注：模拟器上注入双指手势用的 `sendevent /dev/input/event4` 通道在**手势被中途打断**（脚本被 kill）后会卡住，此后原始事件不再被应用接收（`input swipe` 走 InputManager 注入，不受影响）。本次靠重启模拟器恢复，非应用问题。
