## 一、双指纵向缩放价格量程

### 上一版为什么删掉了纵向分量

0.9.2 把双指纵向分量整个删了，理由是「两指张合时 x 间距必然跟着变，纵向张合会被横向分量带偏，用户看到的是『无论上下拉还是左右拉，动的都是横坐标』」。

那个结论**只对「把两个分量混成一个因子」成立**。上一版正是把 dx 与 dy 揉在一起驱动时间轴，于是纵向张合的量从横向那条路漏出去，横轴才跟着动。

### 改法：两个维度各算各的因子

```kotlin
val dx = abs(pressed[0].position.x - pressed[1].position.x)
val dy = abs(pressed[0].position.y - pressed[1].position.y)
// 横向间距 → 时间轴
ChartGesture.pinchFactor(previousDistanceX, dx)?.let { factor ->
    val anchorX = (pressed[0].position.x + pressed[1].position.x) / 2f
    onZoom(factor, anchorX.coerceIn(0f, plot.plotWidthPx))
}
// 纵向间距 → 价格量程；仅当两指都在绘图区
if (pressed.all { it.position.x < plot.plotWidthPx }) {
    ChartGesture.pinchFactor(previousDistanceY, dy)?.let(onPriceZoom)
}
previousDistanceX = dx
previousDistanceY = dy
```

`pinchFactor` 直接复用，语义天然吻合：**拉开 → 因子 < 1**，乘到可见根数上是放大时间轴，乘到价格量程上是量程变小、K 线变高。同一个函数、同一套「拉开 = 放大」。

分开算之后，上下拉开时 dx 基本不变 → 时间轴自然不动；横向张开时 dy 基本不变 → 价格轴不动。两个维度彻底解耦。

纵向限定「两指都在绘图区」，让刻度区里的捏合保持只缩放时间轴的旧行为。

### 顺带修掉的一个跳变

单指分支原先只清 `previousDistanceX`，没清 `previousDistanceY`。从双指抬成单指、再按下第二根时，纵向会拿上一场的旧间距算出因子，缩放瞬间跳一大格。两个都清零。

## 二、缩放时抖动

### 根因：价格基准逐帧重算

```kotlin
val autoRange = remember(series, dataWindow.first, dataWindow.last) { ... }
val mainRange = remember(autoRange, priceZoom, pricePan) {
    autoRange.scaled(priceZoom, autoRange).panned(pricePan, autoRange)
}
```

自动量程由**可见数据窗口**算出，而横向平移/缩放会改可见窗口。于是缩放过程中 `autoRange` 逐帧重算、`mainRange` 跟着跳 —— 价格轴一跳一跳。

手指上下拉开时难免带出一点横向间距变化，于是时间轴也缩放、价格轴跟着跳，两个方向的跳变叠在一起，正是用户看到的「图表缩放时抖动」。

### 改法：手势期间冻结价格基准

```kotlin
/** 手势进行期间冻结的价格基准量程；null = 用实时的自动量程。 */
var priceBase by remember(symbolKey, interval.storageKey) { mutableStateOf<ValueRange?>(null) }
val rangeBase = priceBase ?: autoRange
val mainRange = remember(rangeBase, priceZoom, pricePan) {
    rangeBase.scaled(priceZoom, rangeBase).panned(pricePan, rangeBase)
}
```

- `onGestureStart`：`priceBase = liveAutoRange` —— 整场手势价格轴钉死不动；
- `onGestureEnd`：`priceBase = null` —— 松手后交回自动量程做**一次性**适配。

新区间的价格范围该重新适配，但只需要发生一次，而不是每帧一次。

`onPricePan` 的钳制基准也改用 `liveRangeBase`（冻结值）。原先用 `liveAutoRange`，基准逐帧变会让 `pricePan` 被反复重新钳，拖到边界时手感发涩。

`priceBase` 与 `priceZoom` / `pricePan` 挂同一组 `remember` key，换标的/周期一并复位；`pointerInput` 协程被取消时（key 变化、离开组合）状态也随之重建，不会留下永久冻结。

## 三、验证（模拟器实测）

用 `sendevent` 注入协议 B 多点触控（`/dev/input/event4`，"Xiaomi Input"），模拟器 shell 属于 `input` 组，无需 root。

| 操作 | 结果 |
| --- | --- |
| 绘图区双指纵向拉开（x 固定 400/600，y 间距 200 → 400） | 刻度步长 **2000 → 1000**，K 线纵向放大 ✅；出现「刻度已缩放 · 复位」徽标；**时间轴保持 `09-16 13:00 / 09-19 21:00` 未变** ✅ |
| 绘图区双指纵向合拢（间距 400 → 200） | 步长回到 **2000**、K 线变矮、徽标消失 ✅ |

合拢把量程精确还原（0.5 × 2.0 = 1.0），说明缩放是严格乘性的、无累积漂移 —— 抖动修复没有引入新的偏置。

单测：新增 3 项（纵向拉开使量程收窄且不动点仍是中位价、纵向合拢使量程放宽、横向间距不变时时间轴因子恰为 1），全量 **190 项全绿**。

## 四、遗留

时间轴缩放的提交是**离散**的（可见根数是整数根，`accumulatePinch` 每帧最多提交一根）。缓慢捏合时表现为「一根一根地跳」而非连续平滑 —— 这是整数视窗的固有量化，要根治需把 `ChartViewport` 的 `visibleBars` / `rightOffset` 改为浮点，牵动渲染与全部视窗单测，本次未做。用户报的「抖动」经定位是价格基准跳变（已修），与此量化跳感不是同一回事。
