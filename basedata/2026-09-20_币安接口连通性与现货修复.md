# 币安接口连通性与现货行情修复归档

- 日期：2026-09-20
- 环境：Windows 宿主机 + MuMu12 模拟器（adb 端口 16384），设备型号 vivo V2344A
- 现象：行情页「请求不到数据」，app 显示「网络中断，正在展示最近一次缓存」；另一次表现为首页无限转圈 loading。

## 一、接口连通性结论（大陆网络实测）

| 域名 | 用途 | 宿主机检测 | 模拟器内检测 | 结论 |
|------|------|-----------|-------------|------|
| `api.binance.com` | 现货官方主域 | FAIL（连接被重置） | 未测 | 被墙 |
| `api1/2/3.binance.com` | 现货备用 | 超时 | 未测 | 被墙 |
| `data-api.binance.vision` | 现货行情镜像 | 200，3708 个交易对 | 200，`ticker/24hr` 秒回 | **可用（现货）** |
| `fapi.binance.com` | 合约（USDT-M）官方 | 超时 | HTTP 000 | 被墙，无官方镜像，暂无法直连 |
| `data-api.binance.vision/fapi/*` | 合约镜像猜测 | 404 | - | 不支持合约 |

关键结论：现货唯一大陆可直连的域名是 `data-api.binance.vision`（币安官方行情镜像，仅现货）；合约官方 `fapi.binance.com` 大陆被墙且没有公开的官方合约镜像，需用户提供自建镜像/代理才能使用。

## 二、代码改动

### 改动 1：现货默认域名把可用镜像提到首位
文件：`app/src/main/java/com/waxilo/marketmonitor/data/remote/BinanceMarketApi.kt`：DefaultRestHosts.SPOT
将 `data-api.binance.vision` 从列表末位调到首位。原列表 `api.binance.com → api1~3 → data-api`，被墙主域会逐个走完 connect/read 超时才兜底（每次加载 40s+），看似「请求不到数据」。

### 改动 2：冷启动不再无限 loading（核心 bug）
文件：`app/src/main/java/com/waxilo/marketmonitor/ui/market/MarketViewModel.kt`：init
`selectMarket` 在市场未变化时提前 `return`，而默认市场 SPOT == 初值 SPOT，导致 init 里那次调用直接返回、`refresh()` 从未执行 → 首页永远停在初始 loading 且不发起请求。修复：init 末尾补一次无条件 `refresh()`。

## 三、验证结果（MuMu 模拟器内）
重新构建 + 重装后冷启动：
- 现货「自选」页：loading 正常结束，显示空状态「还没有自选交易对」，无网络中断提示。
- 现货「行情」页：成功显示实时数据（BTCUSDT 80460.49 / ETHUSDT 2587.99 / SOL 108.70 / NEAR 3.55 等，含价格、涨跌幅、成交额、收藏图标）。
- 结论：模拟器内现货行情已能稳定获取数据。

### 改动 3：OkHttp 支持系统代理
文件：`app/src/main/java/com/waxilo/marketmonitor/di/AppContainer.kt`
OkHttp 在 Android 上默认不读取系统（Wi-Fi）代理。新增 `applySystemProxy()` 套到 `restClient` / `wsClient`，`systemProxy()` 依次读取系统属性 `http.proxyHost` 与 `ConnectivityManager.getDefaultProxy()`；系统未配置代理时返回 null、保持直连。minSdk 26 ≥ 23，可直接调用。已重装至模拟器验证：无代理时现货行情仍实时正常，无回归。

## 四、遗留
- 合约（USDT-M）需一条能访问海外 fapi 的通道（自建镜像/代理），用户当前选择「现货先用」，合约暂缓。
- 镜像域名配置入口（设置页）尚未实现，代码已预留 `spotRestMirror` / `futuresRestMirror` / `wsMirror`，见 `domain/repository/AppSettings.kt` 与 `di/AppContainer.kt`。
